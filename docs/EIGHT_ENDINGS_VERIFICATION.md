## 3. 여덟 엔딩 선택 경로

- **기준:** `tests/e2e/eight-endings.spec.ts` 의 `PLANS`(desktop·ipad-webkit 브라우저 E2E 로 통과한 경로). 브라우저 결과는 Linux 의 Chromium/WebKit 에뮬레이션이며 실기기 확인이 아니다.
- **재생 확인:** 경로 담당의 저장소 밖 재생 스크립트(`replay.mts`)가 `45ba37f` 의 실제 대본(`src/story` 의 `STORY`)과 실제 실행기(`src/engine/runner.ts` 의 `newGameState`·`settle`·`advance`·`choose`·`visibleOptions`)로 각 경로를 새 게임 상태에서 엔딩까지 재생했다. **8개 모두 기대 엔딩·루트·해금 여부·판정 점수·첫 루트 장면·장면 순서·CG 목록이 spec 과 일치**(어긋남 0건). 이 문서를 쓰면서 따로 짠 스크립트로 여덟 경로를 다시 재생해 엔딩·루트·해금 여부·판정 점수·첫 루트 장면이 이 표와 같음을 한 번 더 확인했다.
- **표기:** 점수는 아카네/히나/코하루 순서이며 게임 화면에는 보이지 않는다. 옵션 id 는 초반 `a`(아카네)·`b`(히나)·`c`(셋이 함께), 발견 경로 후반 `a`·`b`·`k`(코하루), 미발견 경로 옛 후반 `a`·`b`·`c`, 결말 갈래 `f`(축제)·`d`(일상). 「버튼」은 화면 선택지 버튼의 위에서부터 순서. 문구는 치환 키를 기본 이름(소우타·아카네·히나·코하루…)으로 바꾼 화면 문구 그대로다.

### 규칙

  - 이전은 읽을 때 메모리에서만 일어난다. 결정적이고 멱등이다.

## 8. 에뮬레이션과 실기기 구분

- **실제 iPad Safari, iPhone, Android Chrome 기기에서는 확인하지 않았다.** 1~6절의 브라우저 결과는 모두 Linux 의 Chromium 과 WebKit 기기 흉내다.
- `ipad-webkit` 은 Playwright WebKit 에 `iPad (gen 7) landscape` 기기 설정(옛 iPad UA, `data-render='apple-touch'`)을 씌운 것이다. 실제 iPad 의 렌더링·성능·효과음 지연을 대신하지 않는다. 5절의 효과음 시차(0.29~0.79초)도 에뮬레이션 값이다.
- 실제 기기 성능(프레임·메모리·발열)과 느린 망의 그림 대기 시간을 재지 않았다.
- macOS Safari, Firefox 는 돌리지 않았다.
- 스크린샷 판정은 에이전트가 이미지를 열어 본 것이다. 사람이 화면을 보고 확인한 기록은 없다.
