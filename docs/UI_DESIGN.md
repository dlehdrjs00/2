# 《내일도 같이 갈래?》 UI 디자인 명세 (최종안)

> 방향: **「맑은 여름 하늘」**(우승 시안)을 바탕으로 **「노을과 종이」**(준우승 시안)의 좋은 구조를 접목했다.
> 이 문서는 구현 기준이다. 모든 화면 문구는 한국어로 쓴다.
> 최종 목업은 작업 세션의 임시 폴더(`scratchpad/ui-design/final/`)에 두었고, 저장소에는 포함하지 않는다. 이 폴더는 지워질 수 있다. 그래서 구현에 꼭 필요한 값은 모두 이 문서에 옮겨 두었다.
> - `index.html?s=<화면>`: 한 화면만 보기. 화면 이름은 title, dialogue, choice, save, load, settings, log, card, ending, night, menu, confirm, hide
> - `css/final.css`: 실제 게임의 클래스 이름을 그대로 쓴 스타일
> - `js/mock.js`: 새 배치 공식
> - `scripts/shots.cjs`: 스크린샷 촬영과 자동 점검

## 0. 선정 경위

두 시안의 스크린샷(PC, 휴대폰 가로, 최소 크기, 세로)과 현재 게임 화면을 직접 보고 기준마다 10점 만점으로 매겼다.

| 기준 | 맑은 여름 하늘 (sky) | 노을과 종이 (dusk) |
|---|---|---|
| 상용 비주얼노벨다운 완성도 | **8.5** | 7.5 |
| 작품(여름 학원 러브코미디)과의 어울림 | **9.0** | 7.5 |
| 휴대폰 가로 가독성·터치 | **8.0** | 7.5 |
| 일러스트를 가리지 않는 정도 | 7.5 | **8.5** |
| 구현 가능성 | **8.0** | 7.0 |
| 접근성 | 7.5 | **8.0** |
| **합계 (60점 만점)** | **48.5** | 46.0 |

**우승은 sky다.** 이유는 다음과 같다.
- 장마 끝 초여름의 맑은 하늘과 축제 밤(남색 유리 톤) 양쪽에 자연스럽게 맞는다.
- 흰 유리 UI가 일러스트의 색을 해치지 않는다.
- 기존 DOM과 클래스를 그대로 따르므로 옮기기 쉽다.

sky의 약점과 고친 방법:
- **빠른 메뉴 캡슐이 창과 떨어져 떠 있었다.** 그래서 인물 상반신 위에 UI 덩어리가 하나 더 생긴 것처럼 보였다. 빠른 메뉴를 대사창 위 테두리에 붙은 탭으로 바꿨다. 이름표 탭과 같은 높이의 띠를 나눠 쓴다. 또 대사창 기본 높이를 무대의 25%에서 22%로 줄여 창 위끝을 낮췄다. 3줄 용량은 그대로다.
- **주 버튼 그라데이션 위 흰 글자의 대비가 2.5~3.7:1로 낮았다.** 그라데이션을 바꿔 모든 구간에서 4.5:1 이상으로 맞췄다(3장).

dusk에서 가져온 것:
1. 빠른 메뉴를 대사창에 붙이는 방식과 `.qbar > .hud + .qbar-extra` 구조. `display: contents`와 `order`로 순서를 정한다.
2. 대사창 숨기기 버튼과 H 키
3. 저장·불러오기·설정·기록을 한 오버레이 안에서 탭으로 오가는 **탭 시트**
4. 왼쪽 **쪽 레일**과 수동 슬롯 30칸
5. **일력 모양 날짜 카드**. 하늘 톤으로 다시 칠했다.
6. **폴라로이드 엔딩**. 사진이 취미인 히나라는 작품 소재와 이어진다.
7. 타이틀 [이어하기] 옆의 자동 저장 날짜
8. **글자 크기 설정**과 대사창 불투명도 하한 40

dusk에서 가져오지 않은 것과 이유:
- 크림 종이 질감과 마스킹테이프: 학원 러브코미디보다 회상물 톤에 가깝고, 종이가 불투명해 그림을 무겁게 덮는다.
- 손글씨체(연성): 16px에서 읽기가 떨어진다.
- 노을 타이틀: 지금 타이틀 그림과 맞지 않아 키 비주얼을 새로 그려야 한다.

## 1. 디자인 방향

1. **흰·하늘 반투명 유리.**
   - 모든 창은 흰 유리를 쓴다(블러 14px, 1px 흰 테, 하늘색 바깥선).
   - 축제·밤 배경에서는 남색 유리로 바뀐다(`#vn[data-tone=night]`).
   - UI 바탕은 늘 밝게 두어 고품질 일러스트의 색을 해치지 않는다.
2. **얇은 장식선과 4각 별(✦).**
   - 대사창 안쪽에 장식선을 두르고 네 모서리에 꺾쇠를 단다.
   - 화면 제목 앞에 별을 붙이고, 카드와 엔딩에는 `──✦──` 선을 쓴다. 장식은 1~1.6px 선만 쓴다.
3. **인물 색이 이름표를 칠한다.**
   - 이름표는 대사창 위 테두리 왼쪽에 붙은 탭이다. 위 테두리에 화자 색 띠가 이어진다.
   - 아카네는 적갈, 히나는 장미 분홍, 소우타는 남청, 그 밖의 인물은 회청이다.
4. **조작은 창에 모은다.**
   - 무대 위쪽의 HUD 줄을 없앴다.
   - 빠른 메뉴는 대사창 위 테두리 오른쪽에 붙은 탭이다. 이름표 탭과 같은 높이 띠를 쓴다.
   - 그 결과 일러스트 위쪽(얼굴 부분)이 완전히 비고, 대사창 위끝은 지금(무대 높이의 71%)보다 낮은 76%가 된다.
5. **햇살·빛망울은 멈춰 있는 화면에서만 진하게.**
   - 타이틀, 날짜 카드, 엔딩에서는 진하고, 대사 중에는 위쪽에 옅게 둔다.
   - 설정에서 끌 수 있고, `prefers-reduced-motion`이면 멈춘다.

| 관례 | 흔히 쓰는 곳 | 이 작품에서 |
|---|---|---|
| 대사창 위에 붙은 이름표, 화자별 색 | Ren'Py 기본 GUI(namebox), 유즈소프트·Key 계열 상용작 | 대사창 왼쪽 위 탭 + 위 테두리 화자 색 띠 |

| `--qbar-alpha` | `max(--win-alpha, .82)` | 빠른 메뉴 탭 유리의 불투명도. `.qbar` 가 자기 `--win-alpha` 로 받아 쓰므로 탭 안의 모든 배합(낮·밤·CG·Apple 터치·흐림 미지원)이 이 값을 따른다 |

유리 배합:
- **대사창(낮)**: `linear-gradient(180deg, rgba(255,255,255, a×.96), rgba(244,250,255, a×.90))`, `backdrop-filter: blur(14px) saturate(1.25)`. 여기서 a는 `--win-alpha`다(기본 .70: 대사를 읽으면서 창 뒤 인물의 손·소매·옷 주름이 비치게 82%에서 낮췄다). 글자에는 흰 번짐 `0 0 2px #fff, 0 0 8px rgba(255,255,255,.6)`을 줘서 불투명도를 낮춰도 읽히게 한다.
- **대사창(밤)**: `rgba(26,38,70, a×.9) → rgba(18,26,52, a×.94)`, 글자 `#f4f7ff`(13.9:1), 독백 `#d6e0f5`.
- **레터박스**: 무대 바깥은 어둡게가 아니라 밝게 흐린다. `blur(24px) brightness(1.08)`에 흰·분홍 베일을 덮는다. 밤 톤은 `brightness(.8)`에 남색 베일.
- **페이지 바탕**: `body { background: #dfeefb }`. `<meta name="theme-color" content="#cfe6f8">`, `color-scheme: light`.

이름표 칠: `background: linear-gradient(180deg, var(--name-2) -30%, var(--name-1) 70%)`. 글자 뒤에는 진한 `-1`이 오고, 글자는 흰색이다.
`.textbox[data-who=osana|tenko|me]`가 `--name-1/--name-2`를 고른다. 그 밖의 화자는 npc 색이다. 독백 띠는 하늘색이다.

## 4. 글꼴 토큰

모두 npm 패키지이고 라이선스는 OFL-1.1이다(2026-11-23 `npm view`로 버전과 라이선스 확인). 외부 CDN은 쓰지 않는다.

| 변수 | 패키지 | 굵기 | 쓰는 곳 |
|---|---|---|---|
| `--font-ui` | `pretendard@1.3.9` (`pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css`) | 500/600/700/800 | 버튼·탭·빠른 메뉴·날짜·숫자·패널 본문 |
| `--font-text` | `@fontsource/gowun-dodum@5.3.0` | 400 | 대사, 기록, 선택지, 슬롯 발췌, 카드 부제 |
| `--font-serif` | `@fontsource/gowun-batang@5.3.0` (`700.css`) | 700 | 일력 숫자, 엔딩 제목, 타이틀 부제, 기록 날짜 구분, 폴라로이드 캡션 |
| `--font-deco` | `@fontsource/jua@5.3.0` | 400 | 로고, 이름표, 확인창 질문, 메뉴 제목, 엔딩 배지 |

각 변수의 뒤 순서(폴백): `--font-ui`는 `'Pretendard Variable', Pretendard, 'Apple SD Gothic Neo', 'Noto Sans KR', 'Malgun Gothic', system-ui, sans-serif`다. 나머지도 같은 식으로 시스템 한글 글꼴을 뒤에 둔다.

**크기 규칙.** `fs`는 layout.ts가 계산한 대사 글자 크기다. 가로 화면 휴대폰(667×375 이상)에서 **16px 미만 글자는 없다**.

| 요소 | 크기 |
|---|---|
| 대사 | `fs`, 줄 높이 1.62 |
| 이름표 | `max(17px, fs×0.92)` 주아, 자간 .06em |
| 빠른 메뉴 | `max(16px, fs×0.66)` Pretendard 600 |
| 선택지 | `fs×1.02` 고운돋움, 줄 높이 1.4 |
| 장소 표시 | `max(16px, fs×0.72)` Pretendard 600 |
| 패널 본문 `--ui` | `clamp(16px, fs×0.78, 19px)` |
| 화면 제목·확인창 질문 | `clamp(20px, --ui×1.3, 26px)` 주아 |
| 일력 숫자 / 요일 / 부제 | `fs×4.1` 고운바탕 700 / `max(16px, fs×0.95)` / `max(16px, fs×0.95)` |
| 엔딩 제목 | `clamp(26px, min(3.7vw, 8vh), 50px)` 고운바탕 700, `text-wrap: balance` |
| 로고 1줄 / 2줄 | `clamp(26px, min(4.4vw, 7.6vh), 56px)` / `clamp(42px, min(8.2vw, 13.4vh), 104px)` |
| 토스트·안내·버전 표기 | 16px |

**불러오는 법(`src/ui/styles/tokens.css`, `src/main.ts`가 `styles.css`로 불러온다).**
```css
@import 'pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css';
@import '@fontsource/gowun-dodum/index.css';
@import '@fontsource/gowun-batang/700.css';
@import '@fontsource/jua/index.css';
/* 그 뒤에 타이틀 글자 조각 @font-face 2개(아래) */
```
- 네 패키지 모두 unicode-range로 쪼갠 woff2다. 디스크에는 약 11MB가 생기지만, 실제로는 화면에 나온 글자 조각만 내려받는다. 타이틀 화면에서 받는 글꼴은 11개 212KB이고, 그중 키 비주얼 전에 받는 것은 9개 189KB다(400kbps·Fast 3G 실측이 같음).
- **타이틀 글자 조각 2개(`src/ui/styles/fonts/`).** 로고(주아)와 부제(고운바탕 700)는 몇 글자뿐인데, 패키지 조각에는 글자가 흩어져 있어 타이틀에서만 주아 6개(145KB)와 고운바탕 5개(76KB)를 받았다. 그래서 같은 글꼴에서 그 글자만 뽑은 조각을 따로 둔다. `jua-title.woff2`(`GAME_TITLE` 글자)와 `gowun-batang-700-title.woff2`(`GAME_SUBTITLE` 글자)이고, 각각 약 3.5KB다.
  - `tokens.css`가 패키지 CSS **뒤에** 같은 이름·굵기와 좁은 `unicode-range`로 선언한다. 브라우저는 뒤에 선언한 `@font-face`부터 보므로 이 글자들은 작은 조각에서 받는다. 나머지 글자는 패키지 조각에서 받는다. 글자를 빠뜨려도 깨지지 않고 조각을 더 받을 뿐이다.
  - 원본은 google/fonts의 OFL TTF이고, @fontsource 5.3.0 조각과 외곽선·글자 폭·세로 지표가 같아 글자 모양은 그대로다. 출처와 라이선스는 `docs/ASSETS.md`의 출처 기록에 적는다.
  - 제목이나 부제를 바꾸면 두 파일을 다시 만들고 `unicode-range`를 맞춘다. 만드는 명령은 `tokens.css` 주석에 있다. `tests/unit/layout.test.ts`가 두 조각의 `unicode-range`가 제목·부제 글자와 꼭 같은지, 조각이 패키지 CSS 뒤에 선언되는지 검사한다.
- **숨은 글자 처리.** 브라우저는 *배치된* 글자의 조각을 받는다. `opacity: 0`이나 `visibility: hidden`인 글자도 배치되므로 조각을 받는다. 그래서 타이틀에서 대사 화면 글자의 조각을 받지 않게 두 가지를 둔다.
  - 빠른 메뉴 `.qbar`는 `display: none`으로 만들고(`qbar.ts`), 대사 화면에서만 보인다(`game.ts` `setMode`).
  - 빈 대사창은 줄 상자를 만들지 않는다(`play.css` `.textbox .text .hidden-char:empty { display: none }`). 비어 있으면 보이는 것이 없으므로 모양은 같다.
- `font-display: swap`을 유지한다. 대사 화면 글꼴은 타이틀에서 미리 받되, 키 비주얼이 그려진 뒤(`game.ts` `whenTitleArt`)에 **첫 화면 그림 → 글꼴 → 나머지 그림** 순서로 받는다(느린 망에서 키 비주얼·첫 화면 그림과 대역폭을 나누지 않게, 6.20).
  - 글꼴은 '그려지는 글자'의 조각만 받으므로 첫 화면 글자를 지정해 받는다. 고운돋움은 첫 대사(또는 첫 선택지) 문장, Pretendard 600은 첫 장소 표시 글자, 주아는 그 줄의 이름표 글자다(`game.ts` `loadFonts`가 `document.fonts.load(…, 글자)`로 받는다. 글자는 `firstFrameLines`가 고른다). 빠른 메뉴 탭 글자는 `qbar.preloadFont()`가 탭 버튼의 계산된 글꼴로 받는다(탭은 대사 화면에서만 배치되므로 미리 받지 않으면 첫 장면 그림과 함께 받아졌다).
  - 첫 화면은 자동 저장이 있으면 [이어하기] 위치, 없으면 새 게임 첫 대사다. 첫 화면 글자는 첫 화면 그림을 다 받은 뒤(늦어도 4초 `FIRST_FRAME_WAIT_MS`, 6.20) 받는다.
  - 키 비주얼 전에 대사 화면에 들어갔으면 타이틀 쪽에서는 탭 글자만 받는다. 그 줄 글자는 화면 쪽(`present`)이 받는다. 그림을 기다릴 스텝(배경·인물·CG를 바꾼 스텝, 불러오기·이어하기·복구 직후, 건너뛰기가 멈춘 스텝. 암전 막 포함)이면 기다리기 전에 그 줄의 대사·선택지 문장, 이름표, 같은 묶음 장소 표시 글자의 조각을 요청한다(`stepLines`). 이 규칙은 키 비주얼과 상관없이 모든 그런 스텝에 적용되고, 이미 받은 조각이면 곧바로 끝난다. 건너뛰기 중과 엔딩에서는 받지 않는다.
- 고운돋움의 한글 폭은 1em이므로 `validate.ts`의 `LINE_MAX_CHARS = 88` 가정(최악 1em/글자)은 그대로 성립한다.

## 6. 컴포넌트 규격

### 6.1 무대 `.stage`
- 테두리 `0 0 0 1px rgba(255,255,255,.6)`, 그림자 `0 10px 40px rgba(30,70,120,.25)`. `contain: layout paint`는 유지한다(무대 안 베일과 카드가 대사창을 덮지 않게).
- 인물 `.char`: 드롭섀도 `0 6px 16px rgba(24,60,110,.28)`. 말하지 않는 인물 `.dim`은 어둡게 하지 않고 바래게 한다: `brightness(.9) saturate(.78) contrast(.95)`. 밤·노을 배경에서는 톤별 보정을 건다(6.19).
- 낮 장면에는 `.sunwash`(오른쪽 위 햇빛 번짐, screen 합성)를 깔고, 위쪽에 옅은 빛망울 `.motes`(9개)를 둔다.

### 6.2 대사창 `.textbox`
- 위치·크기: `left: --tx; top: calc(--ty − --tb-grow); width: --tw; height: calc(--th + --tb-grow)`.
- 안쪽 여백: `.95fs 1.35fs .6fs`(지금과 같음). 반경 `fs×.55`.
- 유리: 3장 배합 + `box-shadow: 0 0 0 1px --glass-edge, --glass-shadow, inset 0 1px 0 #fff`.
- 장식:
  - `::before`는 안쪽 장식선이다. inset 5px, 1px `rgba(112,172,226,.3)`, 반경 5px. 네 모서리에 16px SVG 꺾쇠(하늘 선 + 분홍 마름모)를 단다.
  - `::after`는 위 테두리 화자 색 띠다. 높이 3px, `left: fs×.55; right: 18%`, `--name-1 → --name-2 → 투명`.
- 다음 표시 `.next`: 4각 별(하늘→분홍) `fs×.85`, 오른쪽 아래, 1.4s 반짝임.
- 독백 `.mono`: 글자 `--ink-2`, 띠는 하늘색.

### 6.3 이름표 `.textbox .name`
- 대사창 위에 붙은 탭이다. `left: fs×.55; bottom: calc(100% + 1px); height: var(--btn); max-width: 42%`. 위 모서리만 `fs×.5`로 둥글린다.
- 주아, 흰 글자, 앞에 흰 4각 별(.62em). `:empty`이면 숨기고, `aria-hidden`은 유지한다.

### 6.4 빠른 메뉴 탭 `.qbar` (새로 만듦)
```html
<div class="qbar" data-noadvance role="toolbar" aria-label="빠른 메뉴">
  <div class="hud">            <!-- 테스트 훅: 버튼 4개, 글자 '자동' '스킵' '기록' '메뉴' -->
    <button class="hud-btn" data-q="log"><span class="ico" aria-hidden="true"></span>기록</button>
    <button class="hud-btn" data-q="auto" aria-pressed="false">…자동</button>
    <button class="hud-btn" data-q="skip" aria-pressed="false">…스킵</button>
    <button class="hud-btn" data-q="menu">…메뉴</button>
  </div>
  <div class="qbar-extra">
    <button data-q="qsave" aria-label="빠른 저장">…퀵저장</button>
    <button data-q="qload" aria-label="빠른 불러오기">…퀵로드</button>
    <button data-q="hide"  aria-label="대사창 숨기기">…숨기기</button>
    <button data-q="config">…설정</button>
  </div>
</div>
```
- 위치: `right: var(--hr); top: calc(var(--hy) − var(--tb-grow, 0px)); height: var(--btn)`. 아랫변은 대사창 위 테두리와 맞닿는다.
- 모양:
  - 위 두 모서리만 `fs×.5`로 둥글린다. 바탕은 대사창과 같은 흰 유리(q×.90→q×.97)다. 여기서 q는 탭 불투명도 `--qbar-alpha` = max(설정 ÷ 100, .82)다. 대사창의 a(`--win-alpha`)와 따로 둔다.
    - 사용자가 승인한 시안은 대사창 바탕에만 70%를 적용했다. 그래서 기본 70%에서도 탭은 예전 82% 모습 그대로다. 설정이 82% 이상이면 q = a라 예전처럼 대사창과 같이 진해진다.
    - 82% 미만에서는 탭 아랫변이 대사창 윗변보다 진하다. 기본 70%의 낮 장면 기준으로 표준 렌더는 탭 .796, 대사창 .672(Δ.124)다. Apple 터치는 탭 .914, 대사창 .792다.
    - 82% 미만을 저장해 둔 기존 플레이어도 탭은 82% 모습이다. 이전 판에서는 탭이 저장값을 따랐으므로 이 경우 탭이 예전보다 진하다. 대사창 바탕은 저장값 그대로다.
  - 테두리를 `border`로 그리면 버튼 높이가 줄어든다. 그래서 테두리는 모두 `box-shadow`로 그린다(위·좌·우 하늘선과 안쪽 흰 선).
  - 아래 두 모서리에는 `::before/::after`로 10px 오목 이음새를 붙인다. `radial-gradient(circle at 0|100% 0, transparent 9.5px, 유리색 10px)`.
- 순서: `.hud`와 `.qbar-extra`는 `display: contents`로 한 줄에 섞는다. `order`는 기록 1, 자동 2, 스킵 3, 퀵저장 5, 퀵로드 6, 숨기기 8, 설정 9, 메뉴 10이다.
  - 버튼 사이에는 1px 세로 구분선(위아래 30% 비움)을 넣는다.
  - 묶음 경계(퀵저장 앞, 숨기기 앞)는 6px 더 띄우고 구분선을 진하게 한다.
- 버튼:
  - 높이는 100%(=`--btn`, 44~48px), 최소 폭 44px, 좌우 여백 .55em, Pretendard 600, 글자색 `--ink-2`.
  - 마우스를 올리면 `rgba(232,244,255,.9)` 바탕에 `--sky-700` 글자가 된다.
  - 켜짐(`aria-pressed=true`)은 `--grad-on` 바탕에 흰 글자다.
- 폭 단계 `#vn[data-qm]`:
  - `icons`(대사창 폭 900 이상): 아이콘과 글자 8개
  - `full`(620 이상): 글자 8개
  - `compact`(그 미만): `.qbar-extra`를 숨겨 4개만 남긴다. 퀵저장·퀵로드·설정은 메뉴 안에 있고, 단축키 F5·F9·H는 그대로 쓴다.
  - 실측 폭: 1280×720 → 616px(icons), 844×390·667×375 → 429px(full), 740×320 이하·세로 → 192px(compact)
- 밤 톤: 남색 유리 + `#e5ecfb` 글자 + 하늘 구분선(28%).
- 날짜 카드 동안(`data-frame=card`): 창이 없다. 그래서 무대 오른쪽 아래(`top: sy + sh − m − btn`)의 둥근 유리 캡슐로 바꾸고, 불투명도 .78로 둔다(hover·focus 시 1). 이음새는 숨긴다.
- 키: F5 퀵저장, F9 퀵로드, H 숨기기. A, S, L, Esc는 지금과 같다.

### 6.5 대사창 숨기기
- `#vn[data-hidewin='1']`이면 `.textbox`, `.qbar`, `.choices`, `.place-chip`을 `opacity: 0; pointer-events: none`으로 한다(전환 0.25s).
- 아래 가운데에 안내 알약 `.hide-hint`(눈 아이콘 + "화면을 누르면 대사창이 돌아와요", 16px)를 띄운다. 2.4초 뒤 사라진다.
- 숨긴 동안 클릭·탭·Enter·Space·H·Esc는 **복귀만 하고 대사를 넘기지 않는다**.
  - `requestAdvance` 맨 앞에서 처리하고, `lockUi()`로 같은 자리의 두 번째 클릭을 흡수한다.
  - 자동 진행과 스킵은 멈춘다.
  - 선택지 화면에서도 숨길 수 있다. 숨긴 동안 선택지는 누를 수 없다.

### 6.6 장소 표시 `.place-chip`·토스트 `.toast`
- 장소 표시:
  - 무대 왼쪽 위 `left: fs×.8; top: fs×.7`(HUD 줄이 없어져 맨 위로 올라간다).
  - 흰 유리 알약에 해 아이콘(밤은 달)을 단다. 날짜와 장소 사이에 1px `.sep`을 넣는다. 3.2초(`PLACE_MS`) 뒤 사라진다.
  - `place('{d5} · 방과 후 교실')`의 ` · ` 앞부분을 날짜로 나눈다.
  - **배경과 함께 나타난다(`StageView.showPlace`).** 다른 배경을 요청하면 앞 장소 표시는 걷는다. 새 배경이 아직 붙지 않은 동안(`bgPending`: 그 배경이나 같은 묶음 인물 그림의 해독을 기다리는 중, 6.20)에 들어온 장소 표시는 글만 맡아 두었다가(`placeQueued`) 새 배경이 실제로 붙는 순간에 띄운다. 붙는 순간은 해독 뒤 크로스페이드를 시작할 때, 암전 막을 걷으며 `flushBg`할 때, 배경 요청부터 8초(`BG_HOLD_MAX_MS`)가 지나 받는 중인 배경을 그대로 붙일 때다. 앞 장면 배경 위에 새 장소가 먼저 뜨지 않게 하기 위해서다.
  - 3.2초는 같은 묶음의 인물·CG 그림이 붙은 뒤부터 센다(`cgReady`·`charReady`가 모두 풀린 뒤. 늦어도 띄운 때부터 8초 `READY_MAX_MS` 뒤에는 센다). 화면 쪽은 그 그림을 기다려 대사를 그리므로(6.20) 느린 망에서도 첫 대사가 나오기 전에 꺼지지 않는다. 이미 받은 그림이면 곧바로 센다. 새 장소 표시가 뜨면 앞 표시의 늦은 숨김 타이머는 무시한다(`placeToken`).
  - 건너뛰는 중에는 장소 표시를 띄우지 않는다(`game.ts` `applyVisual`). 건너뛰기가 실제로 다음 줄로 넘어갈 때(`present`의 건너뛰기 멈춤 판정 뒤에도 건너뛰기가 켜져 있으면) 떠 있는 장소 표시를 걷고, 새 배경을 기다리며 맡아 둔 장소 표시도 버린다(`stage.hidePlace`, `placeQueued`도 비움). 버리지 않으면 건너뛰는 중에 배경이 붙는 순간 앞 장면 장소 문구가 떠서, 같은 배경으로 이어지는 다음 장면(선택지 화면 포함) 위에 3.2초 남았다. 건너뛰기를 켠 순간(`setSkip`)에는 걷지 않는다. 켜자마자 다음 줄(처음 보는 대사)에서 멈추면 한 줄도 건너뛰지 않았으므로, 맡아 둔 장소 표시는 배경이 붙을 때 그대로 뜬다.
  - **세로 배치(`data-layout=below`)**: 무대가 낮아(390×844에서 약 220px) 알약이 가운데 인물 머리를 가리므로 `StageView.placeHintIn(#vn)`이 장소 표시와 숨기기 안내를 `#vn`으로 옮긴다(무대는 `contain: paint`라 무대 밖으로 못 나간다). 장소 표시는 무대 바로 위 빈 곳 `left: sx + fs×.8; top: max(safe-t + 8px, sy − 8px − 2.3em)`, 폭 상한 `sw − fs×1.6`이다. 위 여백이 모자라면 무대 위끝에 걸친다. 밤·노을 색은 `#vn[data-tone]`으로 같게 칠한다.
  - 선택지 동안에는 세로 배치와 `data-dense` 1~3(낮은 가로), 휴대폰 가로(`data-cgfit='low'`)에서 장소 표시를 감춘다(선택지 첫 줄과 겹치지 않게. 장소 표시 뒤 몇 줄 만에 선택지가 뜨는 c8.ch 에서 844×390·667×375 의 첫 버튼이 아직 떠 있는 장소 표시를 덮었다).
- 토스트:
  - 흰 유리 알약 + 분홍 별, 16px.
  - 플레이 중에는 **무대 오른쪽 위**(`top: sy + fs×.7; right: 무대 오른쪽 + fs×.8`). 자동 저장 상태 표시(6.21)가 그 자리에 떠 있으면(대사·카드, 가로 배치) 그 바로 아래(`top: sy + fs×.7 + btn + 8px`).
  - 선택지 중에는 지금처럼 대사창 안 아래쪽.
  - 세로 배치에서는 대사창 바로 아래 가운데(`top: ty + th + 12px`).
  - 경고 토스트 `.toast.warn`(`role=alert`, 자동 저장을 브라우저에 쓰지 못함 등): 연한 주황 유리(`#5e3206` 글자, 10.2:1) + 주황 세모(`--i-warn`). 자리는 같다. 토스트마다 `data-kind`(테스트·스타일용 표식, 예: `autosave-tab-only`·`autosave-recovered`·`autosave-retry-low`·`autosave-retry-failed`)를 붙일 수 있다.

### 6.7 선택지 `.choices > .choice`
- 영역: 무대 위 여백보다 1px 위(`sy + m − 1`, layout.ts `CHOICE_LIFT`)부터 탭 띠 위 1px(`hy − 1`, layout.ts `CHOICE_CLEAR`)까지. 예전 영역(`sy + m ~ hy − 2`)과 가운데가 같아 버튼 자리는 같고, 3단을 놓을 여유만 2px 늘었다.
  - 버튼과 탭 사이는 목록 안쪽 여백 4px(`CHOICE_PAD_Y`) + 1px + 남는 높이의 절반이다. 그래서 dense 단계 경계에서도 5px 이상이다(포커스 테 3px과 띄움 2px이 탭 띠를 넘지 않음). 740×320에서는 6.07px이다.
  - 가운데 정렬, 스크롤, dense 단계 규칙은 그대로다.
  - **목록 맞춤 `data-fit`**(`game.ts fitChoices`): dense 단계는 한 줄짜리 버튼 기준이라, 두 줄 문구 여러 개가 목록 높이를 넘치면 목록에 `data-fit='tight'`(dense 1 과 같은 촘촘한 모양)를 붙이고, 그래도 넘치면 `'row'`(가로로 나란히)를 붙인다. 선택지를 그릴 때·화면 크기가 바뀔 때·버튼 크기가 바뀔 때(글꼴 도착 등) 다시 잰다(버튼 자리는 등장 연출의 `translate` 와 상관없는 `offsetTop/offsetHeight`). 공통 선택지가 늘 3개라 검사기 한도(`OPTION_MAX_CHARS` 34자) 문구 3개가 667×375 에서 넘치던 것.
- 무대 베일 `.choice-veil`: `radial-gradient(ellipse 70% 60% at 50% 40%, rgba(232,244,255,.22), rgba(36,70,118,.26))` + 블러 1.5px. 두 인물 모두 `.dim`.
- 바:
  - 폭 `min(100%, fs×30)`, 최소 높이 `max(48px, fs×2.55)`(dense일 때 44px), 좌우 여백 2.9em, 가운데 정렬.
  - 배경 `linear-gradient(90deg, 투명, 흰 .93 9%, 흰 .93 91%, 투명)`, 반경 6px, 블러 8px, 그림자.
  - `::before`는 위아래 1px 하늘 장식선(양끝이 사라짐), `::after`는 오른쪽 하늘 마름모 .42em이다.
- 번호 배지 `<span class="num" aria-hidden="true">1</span>`: 지름 1.55em 원, Pretendard 700 `max(16px, .72em)`, 하늘 테.
  - 배지는 absolute라 좌우 여백 2.9em 안에 들어가 줄바꿈에 영향이 없다.
  - 버튼 textContent 앞에 번호가 붙지만, 문구를 비교하는 테스트는 없다(확인함). layout.spec이 textContent를 바꿔 긴 문구를 재는 검사도 그대로 유효하다.
  - 배지를 `::before { content: attr(data-n) }`로 그려도 된다.
- 마우스를 올리거나 포커스하면 분홍 바탕에 `--pink-700` 글자가 되고, 선·마름모·배지도 분홍이 되며 `scale(1.015)`. 고른 것(`.picked`)은 분홍을 유지하고 나머지는 opacity .35.

### 6.10 저장·불러오기 `[data-panel=save|load]`
- 본문은 `grid: auto | 1fr`로, 왼쪽에 **쪽 레일**, 오른쪽에 **슬롯 그리드**를 둔다.
- 쪽 레일 `nav.rail[aria-label=쪽]`:
  - 버튼은 `자동·퀵`, `1`~`5`다. 높이 44px 이상, 폭 64px 이상, Pretendard 700.
  - 현재 쪽은 흰 알약에 왼쪽 하늘→분홍 3px 띠를 붙이고 `aria-current="page"`를 준다.
  - `자동·퀵` 쪽에는 자동 저장과 퀵저장 2칸이 있다. 1~5쪽은 수동 슬롯 1~30(쪽당 6칸)이다.
- **처음 열 때 보이는 쪽**:
  1. 이번 세션에서 마지막으로 본 쪽(메모리에만 저장)
  2. 그런 쪽이 없으면 1쪽
  3. 단, 불러오기 화면에서 1~5쪽이 모두 비어 있고 자동·퀵에 저장이 있으면 `자동·퀵` 쪽
  - 슬롯을 지우거나 저장해서 다시 그릴 때는 지금 쪽을 유지한다.
- 그리드:
  - 넓은 화면은 3열 × 2줄이 남은 높이를 꽉 채운다. 카드는 썸네일(남는 높이 전부) + 정보 2줄이다.
  - 높이 540px 이하 또는 폭 600px 이하에서는 가로형 카드 2열 × 3줄로 바꾸고, 세로 화면에서는 1열 × 6줄로 쓴다.
  - 썸네일은 `min(폭 44%, 카드 높이에 맞춘 16:9)`이다: `width: min(44%, (100cqh − 14px) × 16/9)`, `aspect-ratio: 16/9`(카드 `.slot-wrap`이 `container-type: size`). 카드보다 낮으면 세로 가운데에 두고, cqh를 모르는 브라우저는 폭 44%를 쓴다. 인물·CG가 가장자리에서 잘리지 않는 진짜 16:9다. 정보는 3줄(장면 제목+루트 점 / 날짜 / 발췌)이다.
- 카드 `button.slot[data-slot]`:
  - 흰 유리 82%, 반경 16px, 패딩 8px. 마우스를 올리면 하늘 2px 테. 가장 최근 저장 `.latest`는 분홍 2px 테.
  - `.slot-no`: 썸네일 왼쪽 위 남색 알약 `01`(Pretendard 800, 16px 이상). 자동·퀵 카드는 `자동` / `퀵`.
  - `.slot-route`: 루트 배지(인물 색, 넓은 화면만). 좁은 화면에서는 장면 제목 앞에 9px 점 `.slot-r`.
  - `.slot-name` 700, `.slot-meta` `MM.DD HH:mm`(같은 해면 연도 생략), `.slot-text` 고운돋움 1줄 말줄임.
  - 빈 칸 `.empty`:
    - 하늘 사선 무늬와 점선 테를 두른다.
    - 저장 화면에서는 `.can-save`를 붙인다. 넓은 화면은 썸네일 자리에 "＋ 여기에 저장"을, 좁은 화면은 "＋"를 넣고 제목은 "여기에 저장"(`--sky-700`)이다.
    - 불러오기 화면에서는 `disabled`에 "비어 있음"이다.
  - 손상된 저장: `.broken` 클래스(그대로).
  - **이 탭에만 있는 칸**(브라우저 저장소에 쓰지 못해 이 탭 메모리에만 있음, `SaveManager.slotPersisted(slot)`가 false): `.slot.tab-only`. 발췌 줄 앞에 `.slot-tabonly` 배지 "이 탭에만"(Pretendard 700 16px, `#b35a00` 바탕 흰 글자 4.8:1)을 붙이고, 읽어 줄 이름에 "이 탭에만 저장돼 있어 새로고침하거나 탭을 닫으면 사라져요"를 넣는다. **칸마다 따로 판단한다**(자동 저장·다른 칸의 상태와 섞지 않는다). '장면 처음부터' 배지와 함께면 이 배지가 앞이다.

### 6.11 설정 `[data-panel=settings]`
- 본문 `.panel-body.cfg`는 2열이다: 왼쪽 분류 탭 `clamp(150px, 19vw, 210px)`(휴대폰 138px), 오른쪽 패널.
  - **스크롤은 `.panel-body` 하나**다. 기존 테스트(layout.spec의 설정 터치 스크롤)가 이 요소를 쓴다.
  - 분류 탭과 미리보기는 `position: sticky; top: 0`으로 따라온다.
- 분류 탭 `.tabs[role=tablist][aria-orientation=vertical] > button.tab[data-cfg]`:
  - `글자·대사창` / `소리` / `화면·조작`. 높이 48px(휴대폰 44px).
  - 선택된 탭은 흰 카드에 왼쪽 하늘→분홍 3px 띠다. 화살표 키로 옮겨 다닌다.
  - 세 패널(`role=tabpanel`)은 모두 DOM에 두고 `hidden`만 바꾼다.
- 패널 구성:
  - **글자·대사창**: 글자 속도, 자동 진행 속도, 대사창 불투명도(**40~100**), **글자 크기**(보통·크게·더 크게, `role=radiogroup` 세그먼트) + 오른쪽 미리보기
  - **소리**: 배경음 음량(`data-setting=bgmVolume`), 효과음 음량(`sfxVolume`, 손을 뗄 때 효과음을 낸다)
  - **화면·조작**: 전체화면 스위치, 빛망울 효과 스위치(`particles`), 키 안내 표(`kbd`: Enter/Space/클릭 = 다음, A 자동, S 스킵, L 기록, F5 퀵저장, F9 퀵로드, H 숨기기, Esc 메뉴, 1~3 선택지), 기존 `.setting-note` 문구
- 설정 행 `.setting`:
  - 흰 유리 62%, 반경 14px.
  - 넓은 화면: `라벨 | 값` 한 줄 + 전체 폭 슬라이더 + 양끝 눈금 글자(느리게/즉시, 여유 있게/빠르게, 투명하게/선명하게, 16px `--ink-3`).
  - 높이 540px 이하: `라벨 | 슬라이더 | 값` 한 줄(48px), 눈금 숨김.
- 슬라이더:
  - 입력 높이 44px. 트랙 8px(채운 쪽 하늘→분홍, 나머지 `#dbe7f2`).
  - 손잡이는 26px 흰 원에 2px `--sky-500` 테와 안쪽 하늘 고리를 그린다.
  - 채움 비율은 `--p`로 input 이벤트마다 갱신한다. Firefox는 `::-moz-range-progress`를 쓴다. `touch-action: pan-y`를 유지한다.
- 값 `output`: `--sky-100` 알약에 `--sky-700` 700.
- 스위치: 52×30 트랙, 24px 손잡이, 켜짐은 하늘. 실제 `input[type=checkbox]`를 위에 겹쳐 터치 영역 44px를 확보한다.
- **미리보기** `.preview[aria-hidden=true]`:
  - 16:9(휴대폰 4:3) 작은 무대(교실 배경 + 히나) 위에 실제 `.textbox`를 축소해 붙인다(`--fs: max(16px, 5.2cqw)`, container query).
  - 글자 속도를 바꾸면 예시 문장("이 정도 속도면 읽기 편해? 천천히 골라 봐.")을 처음부터 다시 타자한다. 다 쓰면 자동 진행 속도만큼 쉬고 반복한다.
  - 불투명도와 글자 크기는 즉시 반영한다. 대사창 불투명도 기본값은 70%다(처음 플레이·[기본값으로]). 이미 저장된 설정값은 그대로 쓴다.
    - 설정은 하나만 바꿔도 모든 항목을 함께 저장한다(`saveSettings`). 그래서 이전 판에서 음량·글자 속도 등을 한 번이라도 바꾼 플레이어는 예전 기본 82가 저장돼 있어 계속 82%로 보인다.
    - 직접 고른 82와 구분할 수 없으므로 자동으로 70으로 옮기지 않는다. 70%로 보려면 슬라이더를 70으로 옮긴다. [기본값으로]는 음량 등 다른 설정도 함께 되돌린다.
  - 미리보기 대사창은 실제 플레이 화면의 낮 대사창과 같은 배합이다. Apple 터치 기기에서는 플레이 화면처럼 +0.12 보강을 받는다(performance.css).
  - 미리보기 안 TextBox의 live 영역은 스크린리더가 읽지 않게 한다.
- 바닥줄 `.panel-foot`: "바꾼 설정은 바로 저장돼요."(세로 화면에서는 숨김) · `기본값으로`(.btn) · `닫기`(.btn.primary).

### 6.14 타이틀 `.title-screen`
- 배경: `title` 그림을 꽉 채운다(cover).

### 6.18 이벤트 CG `.stage > .cg-layer`·`#vn[data-cgfit]`·CG 중 유리 (최종 그림 적용)
- 레이어: `.cg-layer`는 무대 가득(`inset: 0`, 바탕색 없음, `will-change: opacity`)이고, 그 안에 그림 한 장 `<img class="cg-img" alt="">`를 둔다(`inset: 0; width/height: 100%; object-fit: cover; object-position: 50% 50%`, 끌기·선택 막음). 쌓는 순서는 배경 → 인물 → 햇빛 → 빛망울 → **CG** → 선택지 베일 → 장소 표시 → 날짜 카드 → 숨기기 안내 → 암전 막 → 불러오는 중 알약이다. 대사창·빠른 메뉴는 무대 밖(`#vn`의 형제)이라 CG 위에 온다.
  - `<img>`는 해독(`decodeOnce`)에 쓴 그 Image를 그대로 붙이고 `decoding='sync'`로 둔다(`paintCg`). `decode()`가 끝난 요소를 붙이면 다음 프레임에 해독 지연 없이 그려지지만, CSS 배경(`background-image`)은 해독 결과를 다시 쓴다는 보장이 없어 늦게 툭 튀어나왔다.
- `StageView.showCg(id)`는 그림 해독이 끝난 뒤에만 `.on`을 붙여 0.55s 페이드로 띄운다. 해독 전에는 무대를 그대로 두고, 파일이 없거나 깨졌으면 끝내 켜지 않는다(바탕색을 칠하지 않으므로 단색 판이 무대를 덮지 않는다). 연출 없이 켜라는 CG(불러오기·건너뛰기)라도 150ms(`LATE_MS`) 넘게 늦으면 페이드로 켠다. 늦음은 해독이 끝난 때 잰다(예열 시간은 넣지 않는다).
- **페이드 전 예열 `.prime`**: 꺼져 있던 레이어를 **페이드로** 켤 때(`animate`, 또는 위의 150ms 늦음)만 먼저 `.prime`(`visibility: visible; opacity: 0.004; transition: none`, 0.004 ≈ 1/255라 눈에 보이지 않음)을 붙여 두 프레임 그린 뒤(`requestAnimationFrame` 두 번, 프레임이 멈춘 숨은 탭을 위해 최대 1.5초 `PRIME_MAX_MS`) `.on`으로 바꾼다. 페이드는 그 0.004에서 이어진다.
  - 까닭: 투명도 0에서 바로 페이드하면 브라우저가 레이어 래스터를 기다리지 않고 애니메이션을 돌린다. 래스터가 느린 환경(GPU 없는 소프트웨어 래스터, 1920×1080 한 장에 0.3~1.1초)에서는 페이드 시간이 빈 레이어로 지나가고 그림이 중간에 툭 튀어나왔다(배경·인물·CG가 함께 바뀌는 c6.a20 등).
  - 연출 없이 켜는 CG(불러오기·건너뛰기, 늦지 않음)는 예열 없이 해독이 끝난 자리에서 바로 켠다. 애니메이션이 없으니 래스터가 끝난 프레임부터 보인다. 예열하면 그 두 프레임(느린 래스터에서 약 0.24초) 동안 CG 없는 배경만 보이다가 늦음 판정으로 페이드했다.
  - 예열이 끝나야 `cgReady`가 풀리므로 대사도 페이드와 함께 나온다(6.20).
  - 이미 켜진 CG를 다른 CG로 바꿀 때는 예열·페이드 없이 같은 레이어의 그림만 바꿔 끼운다(`decoding='sync'`라 래스터가 끝난 프레임부터 보여 앞 그림이 잠깐 비지 않는다).
- CG가 켜져 있는 동안 무대에 `data-cg=<id>`를 단다(레이어에도 같은 `data-cg`).
- **구도 `#vn[data-cgfit]`**(layout.ts, 9.1): 가로 배치에서 탭 띠 위끝 `(hy − sy) / sh`가 `CG_LOW_BAND = 0.66`보다 작으면 `low`(667×375 0.58 · 844×390 0.60 · 932×430 0.63), 그 밖(1280×720 0.695 · 1024×768 0.68 등 넓은 화면, 세로 배치)은 `full`이다. 글자 크기 '더 크게'면 1280×720도 `low`다.
  - `low`에서는 대사의 핵심이 빠른 메뉴 탭·대사창 위끝에 가리는 CG만 확대해 아래 기준으로 붙여 위로 올린다(위쪽이 조금 잘림). 무대와 CG가 모두 16:9라 `object-position`만으로는 움직이지 않아 `.cg-img`에 `transform`으로 크기를 키운다(레이어 밖은 무대 `contain: paint`가 자른다). `scale(k)`를 `transform-origin: x y`에 두면 예전 `background-size: k×100% auto; background-position: x y`와 같은 구도다(그림의 x·y 지점이 무대의 x·y 지점에 고정).
  - `shutter_tenko`(t6.220): `transform: scale(1.3); transform-origin: 30% 100%`. 웃는 입(원본 세로 0.60~0.68)이 탭 위끝 아래로 들어가던 것을 무대 0.48~0.58로 올린다(리본·정수리 일부 잘림).
  - `cats_tenko`(t1.140~): `transform: scale(1.15); transform-origin: 50% 100%`. 히나 옆에 앉은 다이후쿠(원본 세로 0.55~0.62)의 머리가 '기록·자동' 탭 뒤에 가리던 것을 탭 위로 올린다(히나 얼굴은 남는다).
  - `kh_relay`(k5.110~k5.130): `transform: scale(1.15); transform-origin: 50% 100%`. 함께 잡은 안내판(원본 위끝 세로 0.63)이 탭 띠 뒤에 통째로 깔리고 소우타의 손이 이름표에 가리던 것을, 판 위끝·두 손이 탭 띠 위로 보이게 올린다(아호게 끝이 조금 잘림).
  - 선택자는 `.vn[data-cgfit='low'] .cg-layer[data-cg='<id>'] > .cg-img`이다. 그 밖의 CG는 `full`과 같은 구도다. 일러스트를 바꾸면 이 세 규칙(`styles/play.css`)만 다시 잰다.
- **CG 중 대사창·빠른 메뉴 유리**(`.vn > .stage[data-cg] ~ .textbox`, `~ .qbar`): CG의 핵심 동작(맞잡은 손 등)이 대사창 높이에 있는 경우가 많아 유리를 옅고 덜 흐리게 해 그림이 비치게 한다.
  - 불투명도 `--cg-a = clamp(.3, win-alpha² × .78, .8)`(설정 불투명도를 따르되 낮춤: 기본 70% → 약 .38, 82% → 약 .52, 100% → .78, 40% → .3. 탭의 a 는 `--qbar-alpha` 로 계산해 기본에서 약 .52). 대사창은 `rgba(255,255,255,a) → rgba(244,250,255,min(1, a×1.1))`, 탭은 `a×.94 → a`로 칠하고 아래 오목 이음새도 같은 a로 칠한다. 설정이 82% 이상이면 두 a 가 같아 대사창 윗변과 그대로 이어진다. 그보다 낮으면 탭이 대사창보다 진하다. 기본 70%에서 탭 아랫변·이음새와 대사창 윗변은 표준 렌더 .525 / .38(Δ.145), Apple 터치 .624 / .482다. 사용자가 승인한 시안이 대사창 바탕에만 70%를 적용했으므로 탭은 82% 그대로 둔다(6.4 빠른 메뉴 탭 참고).
  - 흐림은 `blur(3px) saturate(1.1)`(평소보다 약함). 글자 읽힘은 흰 번짐(`0 0 2px #fff, 0 0 6px, 0 0 14px`)으로 지킨다. 밤 톤은 남색 유리(`rgba(26,38,70,a)`)에 어두운 번짐이다.
  - 무대의 형제로 고르므로 `:has()`가 필요 없고, 설정 미리보기의 대사창은 건드리지 않는다.

### 6.19 밤·노을 인물 보정 `.stage[data-tone] .char`
- `stage.ts`가 무대에 `data-tone`(배경 매니페스트 `BACKGROUNDS[id].tone`, 기본 낮)을 단다. 낮 색 그대로면 밤 배경 위에서 인물이 오려 붙인 듯 떠 보여 톤별로 필터를 건다. filter 전환(0.35s)이라 배경 크로스페이드와 함께 바뀐다.

| 톤 | 말하는 인물 | 말하지 않는 인물(`.dim`)·선택지 중 |
|---|---|---|
| 낮 | 그대로 + 그림자 `rgba(24,60,110,.28)` | `brightness(.9) saturate(.78) contrast(.95)` |
| 밤 | `brightness(.86) saturate(.88) contrast(.98)` + 남색 그림자 `rgba(10,20,60,.35)` | `brightness(.78) saturate(.7) contrast(.95)` |
| 노을 | `sepia(.08) brightness(.97)` + 붉은 그림자 `rgba(110,50,40,.26)` | `sepia(.08) brightness(.88) saturate(.78) contrast(.95)` |

- 톤 규칙(0,3,0)이 `.char.dim`(0,2,0)을 덮지 않게 dim·선택지 중 바램을 톤별로 다시 건다. 햇빛 `.sunwash`는 노을이면 살구빛, 밤이면 끈다.

### 6.20 그림 기다리기 `StageView.ready()`·`.stage-loading`·미리 불러오기 (느린 망)
목표: 느린 망에서도 덜 받은 그림(위에서부터 띠 모양으로 그려지는 그림)이나 앞 장면과 섞인 무대가 보이지 않고, 대사가 그림보다 먼저 나오지 않는다. 보통 네트워크에서는 이미 받은 그림이라 아래 기다림이 모두 곧바로 지나간다.

**무대(`stage.ts`)**
- 배경·인물·CG는 바꿀 그림을 먼저 해독(`decode()`)한 뒤에만 보여 준다. 그때까지 새 인물은 `.entering`으로 숨긴 채, 표정 교체는 이전 그림, 배경은 이전 배경, CG는 무대 그대로 둔다. 해독에 실패한 그림(파일 없음·손상)은 배경·인물은 그대로 붙이고 CG는 띄우지 않는다.
- **새 배경은 같은 묶음의 인물 그림과 함께 붙는다.** 같은 묶음(`applyVisual`·`renderSnapshot` 한 번처럼 한 동기 흐름, `batchDecodes`)에서 요청된 인물 그림의 해독까지 끝난 뒤에 새 배경을 붙인다. 작은 배경 그림만 먼저 붙어 '새 배경 + 인물 없음' 무대가 앞 대사 아래 남지 않게 하기 위해서다. CG는 기다리지 않는다(CG는 무대 위를 덮으며 따로 페이드로 켜진다. 큰 그림 하나 때문에 배경·인물 교체까지 서 있지 않게). 기다리다 포기한 인물 그림(아래 `ready()`)도 기다리지 않는다.
  - 배경 요청부터 8초(`BG_HOLD_MAX_MS`)가 지나도 아직이면, 막이 있든 없든 받는 중인 새 배경을 그대로 붙인다(`flushBg`: 바탕색 + 받는 대로 그려짐). 배경 요청이 응답 없이 멈춰도 무대가 앞 장면에 고정된 채 새 장면 대사가 흘러가지 않게 하기 위해서다(막 경로의 `VEIL_WAIT_MS`와 같은 값).
  - 이 배경을 기다리던 `ready()`가 시간 초과·누름으로 끝나면(대사가 먼저 그려짐) 같은 묶음 인물은 더 기다리지 않고 배경 자신의 해독만 기다린다. 누른 뒤에는 그림이 준비되는 대로 붙는다.
- **새 배경을 기다리는 동안 인물 교체를 미룬다.** 새 배경이 아직 붙지 않았으면(`bgPending`) 같은 묶음에서 들어온 인물 교체(나가기 `hideChar`, 들어오기·표정·옷·자리 `showChar`)를 새 배경이 실제로 붙을 때까지(`whenBgShown`) 미룬다. 그동안 화면은 앞 장면(배경 + 인물)이 그대로이고, 새 배경이 붙는 순간 배경 크로스페이드와 함께 인물이 바뀐다. 새 장면 인물이 앞 장면 배경 위에 먼저 붙거나, 앞 장면 인물만 먼저 빠져 빈 배경이 보이지 않게 하기 위해서다.
  - 대본은 `hide`를 `bg`보다 먼저 쓰므로 나가기는 한 박자(마이크로태스크) 뒤에 판단한다(같은 묶음의 배경 요청을 볼 수 있게. 화면이 그려지기 전이라 깜빡임은 없다). 들어오기·표정은 그림 해독이 끝난 시점에 배경 대기를 본다(대본에서 `show`가 `bg`보다 앞에 와도 같은 묶음이면 기다린다).
  - 인물의 자리·표정 표식(`pos-*`, `data-expr`, `data-look`)도 그림과 함께 바꾼다(앞 장면 배경 위에서 자리를 옮기지 않게).
  - 장소 표시도 같은 때 나타난다(6.6).
- `ready(ms = 8000)`: **마지막 `ready()` 뒤에 들어온 그림 요청**(`fresh`, 보통 이번 스텝이 바꾼 그림)만 기다린다. 배경은 마지막 배경 요청이 실제로 붙을 때까지(같은 묶음 인물 해독과 `BG_HOLD_MAX_MS`까지 포함), 인물은 인물마다 마지막 요청 그림의 해독, CG는 마지막 CG 요청이 켜질 때까지(예열 `.prime`까지, 6.18)다. 다 준비되면 `true`, 시간 초과나 `hurry()`면 `false`. 이미 해독된 그림이면 마이크로태스크 안에서 끝나 깜빡임이 없다.
  - 부를 때 목록을 비우므로 앞선 `ready()`가 이미 기다린 요청은 다시 기다리지 않는다. 그사이 걷힌 인물·CG(`hideChar`·`showCg(null)`)는 목록에서 빠진다.
  - **포기한 그림(`givenUp`)**: 누름(`hurry`)으로 끝났거나 상한(8초 `READY_MAX_MS` 이상)까지 기다려 시간 초과가 나면, 그때 아직 해독 전이던 그림 주소를 '포기함'으로 둔다. 같은 그림을 다시 요청해도 대사도 같은 묶음 배경도 그 그림을 기다리지 않는다(무대에는 받는 대로 붙는다). 멈춘 그림 하나 때문에 뒤의 줄마다 8초씩 서지 않게 하기 위해서다.
  - 짧게 잡은 기다림(화면 쪽 표정 줄의 1초 `EXPR_WAIT_MS`)이 시간 초과로 끝난 것과, 기다리는 사이 무대 세대가 바뀐(불러오기·타이틀 이동) 기다림은 포기로 보지 않는다. 그래서 뒤에 그 그림이 새로 등장하는 줄은 끝까지 기다린다.
- `hurry()`: 진행 중인 기다림(`ready`와 연출 대기)을 모두 즉시 끝낸다. 그림은 준비되는 대로 따로 붙는다.
- 1.2초(`DECODE_MAX_MS`)가 넘게 기다리면 무대 가운데에 `.stage-loading[role=status]` 알약("그림을 불러오는 중…", 도는 분홍 별, 16px)을 띄운다. 암전 막 위에도 보이도록 무대의 맨 뒤 요소다. 한 번 켜면 최소 0.4초(`LOADING_MIN_MS`)는 보인 뒤 걷는다(켜진 지 0.1초 만에 꺼져 반쯤 보였다 사라지는 깜빡임 방지). 기다림이 여럿 겹치면 모두 끝나야 걷는다. 보통 네트워크에서는 보이지 않는다.
- 암전 막(`veilOut`)도 걷기 전에 `ready(8000)`(`VEIL_WAIT_MS`)을 거친다. 그때까지 새 배경이 붙지 않았으면(시간 초과·누름) 받는 중인 새 배경을 붙이고 걷는다(`flushBg`). 미룬 인물 교체·장소 표시도 그때 풀린다.
- **무대 세대(`gen`)**: 불러오기(`renderSnapshot`)·비우기(`clearAll`)·막 즉시 걷기(`clearVeilInstant`)마다 세대를 올린다.
  - `veilOut`은 막을 친 세대가 지금 세대와 다르면(기다리기 전이든 기다린 뒤든) 아무것도 하지 않고 끝난다. 그때 `bgPending`은 불러온 장면의 배경이라, 여기서 `flushBg`하면 그 배경이 해독 전에 붙고 미뤄 둔 인물 교체까지 함께 풀렸다. 번쩍임(`flash`)은 흰 막을 치기 전의 세대를 `veilOut`에 넘겨 같은 규칙을 따른다.
  - 앞 세대에서 미뤄 둔 퇴장(`hideChar`)은 불러온 배경이 붙을 때 페이드 없이 바로 빠진다(불러온 무대 위에서 앞 장면 인물이 페이드하지 않게).
  - 세대가 바뀌어 끝난 `ready()`는 포기로 보지 않는다(위).

**화면(`game.ts` `present`·`requestAdvance`)**
- 대사·선택지·카드를 그리기 전에 `stage.ready()`를 기다린다(`waitStageReady`). 얼마나 기다릴지는 스텝이 무엇을 바꿨는지로 정한다.
  - **끝까지(최대 8초) 기다린다**: 배경(`bg`)이나 CG(`cg`)를 바꿨거나 새 인물이 등장한 스텝(`show`의 `entering`), 불러오기·이어하기·'장면 처음부터' 복구 직후(`fromLoad`·`restored`), 건너뛰기가 이 스텝에서 멈춘 스텝.
  - **잠깐만(최대 1초 `EXPR_WAIT_MS`) 기다린다**: 그 밖에 이미 무대에 있는 인물의 표정·옷·자리만 바뀐 스텝(`show`). 그동안 이전 그림이 그대로 보이므로 덜 받은 그림은 보이지 않는다. 늦으면 대사가 먼저 나오고 표정은 그림이 준비된 뒤에 바뀐다(느린 망에서 표정 한 장 때문에 대사가 몇 초씩 막히던 것). 1초는 '불러오는 중' 알약(1.2초)보다 짧아 이 스텝에서는 알약이 뜨지 않는다. 1초가 지나 시간 초과로 끝나면 포기로 보지 않는다(위 `ready()`. 뒤에 그 그림이 새로 등장하는 줄은 끝까지 기다린다). 기다리는 동안 누르면(`hurry`) 다른 기다림처럼 그때 해독 전인 그림을 포기로 본다.
  - **기다리지 않는다**: 무대 그림을 바꾸지 않은 스텝(퇴장·장소 표시만 있는 스텝 등), 건너뛰기 중, 엔딩 스텝. 암전·번쩍임 막이 이미 기다린 스텝은 한 번 더 기다리지 않는다.
- 기다리는 동안은 `transitioning`이라 클릭·키는 대사를 넘기지 않고 `stage.hurry()`로 기다림만 끝낸다(대사가 곧바로 그려진다). 선택지 스텝도 같다. 선택지가 그려지기 전(그림 대기·암전 연출 중)에 누른 진행 키(Enter·Space·→·PageDown)와 숫자 키는 클릭처럼 기다림만 끝내고 선택지를 고르지 않는다(숫자 키로 고르는 것은 선택지가 나타난 뒤다). 자동 진행 타이머는 대사가 그려진 뒤에 걸린다. 기다리는 중에 건너뛰기를 켜면 기다림을 끝내고 대사를 즉시 표시한다.
- **대기 뒤 연타 잠금 `HURRY_LOCK_MS = 400`**: 그림 대기를 누름으로 끝냈으면 그 뒤 400ms 동안은 입력이 대사를 넘기지 않는다(`hurryLockUntil`). 같은 연타(더블클릭·더블탭·키 연타)의 둘째 입력이 기다리던 줄을 한 프레임만 보이고 넘기던 것(글자 속도 '즉시'에서 두드러짐)을 막는다. 이 동안에도 타자 효과 마무리(타자 중이면 둘째 입력으로 완성)는 된다. 다른 '더블클릭 나머지' 흡수(`UI_LOCK_MS`·`START_LOCK_MS`)와 같은 길이다. 암전·번쩍임 연출 중의 누름은 연출만 줄이므로 잠그지 않는다.
- **늦게 처리된 대기 중 입력 `stageWaitSpan`**: 그림 대기가 끝나면 기다린 구간(시작·끝 시각)을 남긴다. 입력이 일어난 시각(이벤트 `timeStamp`, `eventTime`)이 그 구간 안이면, 대기가 저절로 끝난 뒤에 처리됐더라도(그림이 막 준비돼 대사를 그리느라 메인 스레드가 바빴던 때) 기다림을 끝내려던 누름으로 본다. 방금 그린 줄을 넘기지 않고 연타 잠금만 건다.
- **누름 반응 `WAIT_FEEDBACK_MS = 60`**: 기다림이 60ms를 넘으면 이전 대사의 '다음' 표시(반짝이는 별, `.textbox.done .next`)를 걷어 누른 것이 먹혔음을 보인다. 곧바로 끝나는 기다림(이미 해독한 그림)에서는 건드리지 않는다(별 깜빡임 없음). 새 대사가 그려지면 대사창이 다시 켠다.
- **그 줄 글꼴 조각**: 그림을 기다릴 스텝이면(암전 막 포함) 기다리기 전에 그 줄 글자의 글꼴 조각을 요청한다(4장 '불러오는 법', `stepLines`). 키 비주얼 전에 게임을 시작했거나 처음 나오는 글자 조각이면 대사를 그리는 순간에야 요청되어 첫 문장이 대체 글꼴로 나왔다 바뀌었다.

**미리 불러오기(`screens/preload.ts` `ImagePreloader`, 순서는 `game.ts` `preloadFrom`)**
- 범위는 지금 위치 다음 스텝부터 지금 장면 끝과 바로 다음 장면까지다(`nearbyImages` → `sceneImages`). 대본(배경·등장·표정 변화·CG)을 **실행 순서대로** 훑어 그림마다 처음 쓰이는 곳까지의 블로킹 스텝(대사·카드·선택지) 수를 잰다. 지금 상태(점수·플래그·선택 기록·루트)의 복사본으로 실행기와 같은 규칙을 따른다: `goto`·`if`(`when`)를 따르고, 숨은 등장 판정(`unlock`)·루트 결정(`decideRoute`)·루트 분기(`routeBranch`)도 지금 상태로 판정한다. 아직 고르지 않은 선택지에서는 **보이는 옵션**(`visibleIf`)마다 갈래를 나눠 각 갈래를 따라가고, 그 뒤의 그림은 갈래 그림(`branch`)으로 표시한다(여러 갈래에서 쓰이면 가장 가까운 거리, 한 갈래라도 선택과 상관없이 쓰이면 갈래 표시 없음). 고르지 않은 선택지 뒤의 `unlock`은 '해금 안 됨'으로 본다. 그래서 해금되지 않은 플레이에서는 히든 히로인 전용 그림을 미리 받지 않는다. 다음 장면은 이 장면을 지나온 상태로 훑는다.
- 순서:
  1. 지금 위치에서 블로킹 스텝 3개 안(`PRELOAD_DECODE_STEPS`, 아래 미리 해독)에서 처음 쓰는 그림은 당김과 상관없이 맨 앞이다(가까운 것부터). 당김이 너무 크면 바로 다음 몇 줄의 표정 그림이 CG에 밀려 늦게 떴다. 갈래 그림은 여기서 뺀다(아래 미리 해독).
  2. 나머지는 '거리 − 당김' 순이다. CG·배경은 같은 거리의 스프라이트보다 12·6스텝 먼저 받는다(`PRELOAD_LEAD`). 단 지금 장면 안에서 아직 고르지 않은 선택지 뒤의 CG(갈래마다 한 장, `branch`)는 당기지 않는다. 고르기 전에는 그중 반은 쓰지 않는데, 큰 CG 두 장이 동시 받기 자리를 차지해 바로 몇 줄 뒤의 표정 그림이 늦었다. 다음 장면(`jump`·`routeBranch`) CG는 그 장면 안의 선택지 뒤가 아니면 갈래 표시가 없으므로(위 범위) 지금 장면에 고르지 않은 선택지가 있어도 12스텝 당김을 그대로 받는다.
  - 당긴 거리가 15스텝 이하(`PRELOAD_NEAR_STEPS`)이면 가까운 묶음, 그보다 멀면 '곧 쓸 그림'으로 나머지 대기열 맨 앞에 둔다. 나머지 대기열은 곧 쓸 그림 → 게임 전체 그림(`allImageUrls`) 순이다. 가까운 묶음을 받는 동안에는 나머지를 새로 시작하지 않는다.
- 동시에 3개(데이터 절약 모드·2G/3G로 보이는 연결은 2개)까지, `fetchPriority: 'low'`로 받는다. 나머지 대기열은 한 자리를 남겨 둔다(가까운 묶음이 새로 들어오면 바로 시작하게). 스텝마다 지금 위치 기준으로 다시 세운다(`preloadFrom`). 무대 그림을 기다린 뒤에 세운다.
- **멈춘 받기 `FETCH_SLOT_MS = 30000`**: 미리 불러오기 한 장이 30초 넘게 걸리면 동시 받기 자리만 비운다. 요청은 끊지 않고, 늦게라도 다 받으면 받은 것으로 친다(다시 요청하지 않음). 응답 없이 멈춘 가까운 묶음 요청 하나가 나머지 대기열을 영영 막지 않게 하기 위해서다. 느린 망(2G 수준)에서는 큰 CG 한 장이 정상적으로 그만큼 걸릴 수 있어 넉넉히 잡았다.
- **무대 그림을 받는 동안 멈춤 `hold`**: `present`는 이번 스텝 무대(배경·인물·CG, `stageImageUrls`)의 그림을 다 받을 때까지 미리 불러오기의 새 받기·해독을 시작하지 않는다. `fetchPriority: 'low'`는 요청을 '시작하는 순서'에만 듣고 이미 받는 중인 요청끼리 대역폭을 나누는 데에는 듣지 않아서, 느린 망에서 이어하기·장면 진입 때 몇 스텝 뒤의 CG·다음 장면 그림이 지금 무대 그림과 함께 받아져 둘 다 늦었다.
  - 상한은 **그림마다 처음 붙잡은 때부터** 20초(`HOLD_MAX_MS`)다. `present`가 스텝마다 다시 붙잡아도 늘지 않는다. 늘리면 멈춘 요청 하나에 상한이 '마지막 스텝부터 20초'가 되어, 한 줄씩 넘기는 동안 미리 불러오기가 끝없이 멈췄다.
  - 상한에 걸린 그림은 붙잡힘에서 뺀다(지켜보는 Image는 계속 받는다). 그리고 다시 붙잡지 않는다(`gaveUp`).
  - `present`는 지금 무대 그림 전부를 넘긴다(`only`). 붙잡고 있던 그림 중 그 목록에 없는 것(무대에서 걷힌 CG, 타이틀에서 붙잡았지만 새 게임에서는 쓰지 않는 [이어하기] 위치 그림 등)은 놓아 준다(`letGo`). 지켜보는 Image만 받던 그림이면 받기를 거둔다.
  - 이미 받은 그림은 붙잡지 않는다. 이미 받는 중인 미리 불러오기는 그대로 둔다. 무대가 같은 주소를 받는 중이면 브라우저가 한 요청으로 합친다. 건너뛰는 중과 엔딩은 붙잡지 않는다(붙잡던 것도 놓는다). 건너뛰기가 이 스텝에서 멈췄으면 이 스텝은 그림을 기다리므로 붙잡는다.
  - 무대가 그림을 해독하며 기다리는 동안(`waitStageReady`)에도 `pauseUntil(ready)`로 새 받기·해독을 멈춘다(Chromium은 같은 때 요청된 해독을 한꺼번에 끝내므로 미리 해독이 끼면 무대 쪽 해독도 늦어진다).
- **3스텝 안 그림 미리 해독**: 지금 위치에서 블로킹 스텝 3개 안(`PRELOAD_DECODE_STEPS = 3`, 0 = 바로 다음 줄)에서 처음 쓰는 그림은 받은 뒤 `decode()`까지 해 둔다(가까운 것부터, 한 번에 하나). 무대는 처음 쓰는 그림을 해독한 뒤에야 대사를 그리므로 그 줄에서 해독을 기다리지 않는다(Chromium에서 받기만 한 그림 20~100ms → 미리 해독한 그림 0~5ms). 해독본은 한 장에 약 8MB라 해독 캐시를 넘치지 않게 몇 줄 안만 해독하고, 해독한 Image는 최근 8장(`HOT_MAX`, Apple 터치 기기 4장)만 붙잡아 둔다.
  - 아직 고르지 않은 선택지 뒤에서만 쓰는 그림(갈래 그림)은 미리 해독하지 않고 받기만 한다. 갈래마다 따로 훑으므로 모든 갈래의 첫 몇 줄이 같은 거리가 되어, 선택지 3개에서 고르지 않을 갈래의 CG·표정까지 해독하면 해독 대상이 2~3배로 늘고 붙잡기 한도를 넘었다. 고른 뒤에는 그 갈래가 갈래 표시 없이 다시 계산되어 평소대로 해독한다.
- **히든 히로인 전용 그림**(스프라이트·전용 배경, `hiddenImageUrls`)은 게임 전체 그림(`allImageUrls`)에서 빼고, 해금된 플레이(`kh.met = true` 또는 그 루트)에서만 나머지 대기열 뒤에 더한다. 타이틀에서 해금된 [이어하기] 위치로 대기열을 세웠다가 새 게임·미해금 저장 불러오기로 바뀌면, 그 순간(첫 화면 그림을 받기 전) 그 인물 그림(전용 그림 + 숨은 CG, 가까운 묶음에서 밀려난 것 포함) 중 아직 받기 시작하지 않은 것을 대기열에서 뺀다(모든 환경).
- **타이틀에서: 첫 화면 그림 → 글꼴 → 나머지.** 타이틀 키 비주얼이 그려진 뒤(늦어도 15초 `TITLE_ART_WAIT_MS`. 데이터 절약 모드는 원본을 받지 않으므로 곧바로, 6.14)에 시작한다.
  1. 첫 화면 그림: 자동 저장이 있으면 [이어하기] 위치의 무대, 없으면 새 게임 첫 대사의 무대(실행기로 첫 블로킹 스텝까지 진행한 복사본, `firstFrame`)를 `hold`로 혼자 먼저 받는다. 대사는 이 그림을 기다리므로 가장 먼저다. `only`라 게임에서 돌아왔을 때 붙잡고 있던 앞 무대 그림은 놓아 준다.
     - 4초(`FIRST_FRAME_WAIT_MS`)는 '글꼴·나머지 미리 불러오기를 시작할 때'일 뿐이다. 이 `hold`는 `giveUp: false`라 4초가 지나 붙잡힘에서 빠져도 그 그림을 포기하지 않는다. 그래서 타이틀에 오래 머문 뒤 [이어하기]를 눌러도 `present`가 그 그림을 다시 붙잡는다(그때부터 20초).
  2. 첫 화면 글자의 글꼴 조각: 첫 대사·이름표·장소 표시 글자와 빠른 메뉴 탭 글자(4장 '불러오는 법'). 1의 그림을 다 받았거나 4초가 지난 뒤 요청한다.
  3. 나머지 미리 불러오기(`startPreload`, 키 비주얼 뒤 0.3초): 타이틀 다음 첫 화면(1과 같은 기준, `firstFrameState`)의 다음 스텝부터(`preloadFromTitle`. 자동 저장이 있으면 [이어하기] 위치, 없으면 새 게임 첫 대사 기준. 첫 화면을 계산하지 못하면 새 게임 첫 장면 처음부터) → 게임 전체. 데이터 절약 모드면 게임 전체는 받지 않는다. 대기열은 이때 세우지만, 붙잡은 첫 화면 그림을 받은 뒤(늦어도 4초 뒤)부터 받기 시작한다. 게임에서 타이틀로 돌아오면 이 기준으로 대기열을 다시 세운다(마지막으로 보던 위치의 그림이 계속 앞에 서 있지 않게).
  - 게임을 시작하면(대사 화면) 키 비주얼을 기다리지 않고 받던 원본을 취소한 뒤 곧바로 시작한다. 이때 타이틀 쪽에서는 빠른 메뉴 탭 글자만 받고, 그림 순서와 그 줄 글자는 `present`가 맡는다(4장).

### 6.21 자동 저장 상태 `.autosave-chip`·경고 토스트 (`src/ui/savestatus.ts`)
목표: 플레이 중 저장 공간 부족 등으로 자동 저장을 브라우저에 쓰지 못하면, 새로고침·탭 닫기 때 최근 진행이 사라질 수 있다는 것을 **바뀌는 순간 한 번** 알리고, 그동안 **확인할 수 있는 표시**를 계속 둔다. 매 대사마다 알리지 않는다.

- **판단(엔진)**: `KeyValueStore.isPersisted(key)` — 그 키의 지금 값이 브라우저 저장소에 그대로 들어 있는가(`BrowserStore`: 읽기 실패 없음 && 그 키가 메모리 대체 저장소에 없음, 메모리 저장소: 테스트용 영구 흉내일 때만). `SaveManager.saveSlot(slot, …)`이 쓰기 결과와 이 판단을 합쳐 `'persisted' | 'tab-only'`를 돌려준다(메모리 저장소는 쓰기가 늘 성공하므로 쓰기 결과만으로는 알 수 없다). `slotPersisted(slot)`·`slotDurability(slot)`는 칸 하나만 본다. 저장소 전체 기준 `persistent`는 칸 판단에 쓰지 않는다.
- 쓰기에 실패해도 다른 칸이나 그 칸의 옛 영구 저장본을 지워 공간을 만들지 않는다. 같은 탭에서는 `get`이 메모리 값(최신)을 먼저 보고, 새로고침하면 브라우저에 남은 옛 값을 본다. `getPersisted`·`peekPersisted`는 새로고침하면 보게 될 값이다.
- `BrowserStore`의 '읽기 실패' 표시는 다음 읽기나 쓰기가 성공하면 풀린다(한 번의 일시적인 읽기 실패로 모든 칸이 계속 '이 탭에만'으로 보이지 않게).
- `openStore()`: 읽을 수 있으면 시험 쓰기가 **용량 초과**로 실패해도 브라우저 저장소를 쓴다(가득 찬 채로 새로고침해도 이전 저장을 불러온다). 단 저장소가 **비어 있는데** 한 글자도 못 쓰면(용량 0, 예: 옛 iOS Safari 사생활 보호 모드) 처음부터 쓸 수 없는 것으로 보고 메모리 저장소(타이틀에서 알림). 읽기 실패·용량 초과가 아닌 쓰기 실패도 메모리 저장소.
- **여유 공간 재기** `KeyValueStore.hasRoom(chars)`·`SaveManager.hasRoom`: 임시 키 `__vn_room__`에 글자 chars 개를 써 보고 곧바로 지운다(`ashita.` 키가 아니라 다른 탭의 storage 이벤트 처리는 무시). 가득 찬 저장소에서도 **같은 칸을 같거나 더 짧은 값으로 덮어쓰는 것은 성공**하므로(브라우저는 늘어나는 만큼만 따진다) 쓰기 하나의 성공으로는 공간이 생겼는지 알 수 없다. 대화 기록이 상한(120줄)에 닿으면 자동 저장 크기가 줄마다 오르내려(실측: 60줄 사이 최대 약 500자) 성공·실패가 번갈아 난다.
- **상태 기계** `AutoSaveTracker`(`savestatus.ts`, DOM 없음 — `tests/unit/autosave.test.ts`가 실제 대본과 '늘어나는 만큼만 따지는' 가짜 저장소로 검사): `none`(자동 저장 없음·아직 안 씀) / `ok` / `tab-only`(마지막 자동 저장이 이 탭에만) / `low-space`(쓰기 실패 뒤, 마지막 자동 저장은 브라우저에 들어갔지만 여유 공간이 거의 없음). 자동 저장을 쓸 때마다 **자동 저장 칸만 보고** 정한다(다른 칸·전역 기록과 섞지 않는다). 타이틀을 오가도 유지하고, 엔딩으로 자동 저장을 지우면 조용히 `none`. 상태는 늘 실제 저장 여부를 따른다(`tab-only`가 아니면 브라우저의 자동 저장이 지금 위치).
  - 실패하면 `tab-only`. 문제 구간(`tab-only`·`low-space`) 안에서 저장에 성공하면 여유 공간 `AUTOSAVE_HEADROOM`(4096자)을 재 보고, 있으면 `ok`(회복), 없으면 `low-space`. 문제 구간 밖에서는 재지 않는다.
  - **알림은 문제 구간이 시작하고 끝날 때만**: `none|ok → tab-only` 경고 토스트(`role=alert`, 7초) "자동 저장을 브라우저에 쓰지 못했어요(저장 공간 부족 등). 지금부터의 진행은 이 탭에만 남아, 새로고침하거나 탭을 닫으면 최근 진행이 사라질 수 있어요." / `tab-only|low-space → ok` 회복 토스트(5초) "자동 저장을 다시 브라우저에 남겼어요 · 새로고침해도 지금 위치부터 이어 갈 수 있어요"(상태 표시를 걷는다). `tab-only ↔ low-space`는 알리지 않고 상태 표시의 글자만 바뀐다.
  - 안전장치: 회복 알림은 60초(`AUTOSAVE_REPEAT_MS`) 안에 다시 띄우지 않는다(그 사이에도 상태와 상태 표시는 바뀐다). 경고는 제한하지 않는다 — 회복 알림 직후 다시 실패해도 경고를 띄운다(마지막으로 본 알림이 '회복'인 채 진행을 잃지 않게).
  - 처음부터 브라우저 저장소를 쓸 수 없으면(타이틀에서 이미 알림) 플레이 첫 진입 때만 짧게(5초, 페이지마다 한 번) "브라우저 저장소를 쓸 수 없어 진행이 이 탭에만 남아요 · 새로고침하거나 탭을 닫으면 사라져요".
  - `#vn[data-autosave]`에 상태를 둔다. `?debug`의 `__vn.info().autoSave`로 읽는다.
- **상태 표시** `button.autosave-chip[data-noadvance][aria-haspopup=dialog][data-state]`(`#vn` 바로 아래): 경고 세모 + 글자(Pretendard 700 16px, `#7a3f08` 글자 / 연한 주황 `rgba(255,243,209,.96)` 7.5:1, 주황 1.5px 안쪽 테). `tab-only`는 "이 탭에만 저장됨", `low-space`는 "공간 부족 · 저장됨". 높이 = 탭 띠 `--btn`(44~48px), 최소 폭 44px. 플레이 중 `tab-only`·`low-space`일 때만 보인다.
  - 대사·날짜 카드: **무대 오른쪽 위**(토스트 자리, 토스트는 그 아래로). 장소 표시(왼쪽 위)는 알약 폭(`--asw`, ResizeObserver)만큼 최대 폭을 줄인다.
  - 선택지: 선택지 목록이 무대 위쪽부터 쓰므로 **탭 띠의 빠른 메뉴 왼쪽**(`right: hr + qbw + 14px`, 선택지 동안에는 이름표가 없다). 빠른 메뉴 compact 단계에서는 앞부분("이 탭에만"·"공간 부족")만 남긴다(`.lbl-x` 숨김, 접근 이름은 그대로).
  - 세로 배치: 무대가 좁아(390px) 장소 표시와 같은 줄에 두면 장소명이 잘리므로, 무대 위 여백의 **장소 표시 줄 바로 위 오른쪽**(`#vn[data-aschip=above]`, `top: 장소 표시 위끝 − 8px − btn`). 위 여백이 모자라면(`data-aschip=under`, `autosaveChipRow`) 장소 표시 줄 바로 아래 오른쪽(무대 위끝에 걸침). 어느 쪽이든 장소 표시의 폭은 줄이지 않는다. 360×640·375×667·390×844는 모두 위 줄.
  - 대사창 숨기기(H) 동안에는 감춘다. 오버레이가 열리면 다른 화면처럼 `inert`.
  - 장소 표시·이름표·빠른 메뉴·선택지·토스트·일력과 겹치지 않는다(1280×720·844×390·667×375·세로 390×844, `tests/e2e/autosave.spec.ts`).
- **설명 패널**(상태 표시를 누르면, 확인창 재사용). 열 때 떠 있는 자동 저장 알림 토스트는 걷는다(같은 내용이고, 낮은 가로 화면에서는 아래 가운데 토스트가 설명창 버튼을 가린다).
  - `tab-only`: "자동 저장이 이 탭에만 있어요" — 새로고침·탭 닫기 때 최근 진행 손실, 브라우저에 남아 있는 자동 저장의 위치(장면 제목 · 저장 시각) 또는 남은 것이 없음, 해결 방법(쓰지 않는 저장 칸 지우기·다른 사이트 데이터 정리·사생활 보호 창은 공간이 작음).
  - `low-space`: "저장 공간이 거의 없어요" — 지금 위치까지는 브라우저에 들어가 새로고침해도 여기서 이어지지만, 다음 자동 저장이 다시 실패할 수 있고 그러면 최근 진행이 사라질 수 있음 + 같은 해결 방법.
  - [닫기] / [지금 다시 저장](자동 저장을 곧바로 다시 쓰고 여유 공간도 다시 잰다. 사용자가 누른 것이라 반복 제한과 상관없이 결과를 늘 알린다: 회복 "자동 저장을 다시 브라우저에 남겼어요 …" / 저장됐지만 공간 부족 "지금 위치를 브라우저에 저장했어요 · 저장 공간이 거의 없어 다음 자동 저장이 다시 실패할 수 있어요" / 실패 "아직 브라우저에 저장하지 못했어요 …"). 처음부터 저장소를 쓸 수 없으면 다시 저장할 수 없으므로 [확인]만.
- **같이 바뀌는 곳**: 저장 화면 칸 배지·안내 줄(6.10), 타이틀 [이어하기] 표시(6.14), [타이틀로] 확인창(자동 저장이 이 탭에만이면 "지금 위치는 이 탭에만 자동 저장되어 있어요" + 새로고침·탭 닫기 손실), 퀵저장·수동 저장 안내(그 칸 기준: 영구면 "슬롯 4에 저장했어요", 쓰기 실패면 "용량이 부족해 이 탭에만 저장됐어요 · 새로고침하거나 탭을 닫으면 사라져요", 저장소를 쓸 수 없으면 "… · 새로고침하거나 탭을 닫으면 사라져요"), 타이틀 안내(저장소를 쓸 수 없으면 "브라우저 저장소를 쓸 수 없어 저장이 이 탭에만 남아요.").

## 9. 반응형 규칙

### 9.1 배치 공식 (`src/ui/layout.ts`)

`scale`은 글자 크기 설정의 배율이다(보통 1, 크게 1.12, 더 크게 1.25). 가로/세로는 안전 영역 비율 `aw / ah ≥ 1.3`으로 가른다.

가로(overlay):
```
fs     = clamp(sh × 0.034 × scale, 16 × scale, 26 × scale)
margin = max(8, sh × 0.022)                                          → --m
th     = clamp(max(sh × 0.22, textBoxHeightFor(3, fs)), 0, sh × 0.45) (3줄 용량은 늘 보장)
tw     = min(sw − margin×2, fs × 46);  tx = sx + (sw − tw)/2;  ty = sy + sh − th − margin
btn    = clamp(fs × 1.75, 44, 48)       (TAB_MIN·TAB_MAX: 휴대폰 가로도 터치 44px)
hy     = ty − btn                       (이름표·빠른 메뉴 탭 띠 위끝)
hr     = vw − (tx + tw) + fs × 0.55 + 10
cy     = sy + margin − 1;  ch = max(0, hy − 1 − cy)   (CHOICE_LIFT = 1, CHOICE_CLEAR = 1)
cx/cw  = 레터박스가 있으면(aw − sw > 2) 안전 영역 폭(safe.l + m, aw − 2m), 아니면 무대 폭
cband  = cy − sy                        (호환용으로만 둔다)
qm     = tw ≥ 900 ? 'icons' : tw ≥ 620 ? 'full' : 'compact'
cgfit  = (hy − sy) / sh < 0.66 ? 'low' : 'full'               (CG_LOW_BAND, 6.18)
```

세로(below):
```
fs  = clamp(aw × 0.042 × scale, 16 × scale, 22 × scale)
btn = clamp(fs × 1.75, 44, 48)
gap = btn + 8          (무대와 대사창 사이에 이름표·빠른 메뉴 탭이 들어간다)
sh  = aw / (16/9);  넘치면 sh = max(ah × 0.45, ah − gap − fs × 7.2)
th  = clamp(ah − sh − gap − 10, fs × 7.2, fs × 10);  tw = min(aw − 16, fs × 40)
hy  = ty − btn;  cy = sy + 7;  ch = max(0, hy − 1 − cy);  cx = safe.l + 8, cw = aw − 16   (cy = sy + m − 1, m = 8)
cgfit = 'full'         (대사창이 무대 아래라 CG 를 가리지 않는다)
```

| 740×232 (지원 범위 밖) | 16 | 104 | 396 | 32.6% | 68 | 3 | compact | low |
| 390×844 (세로) | 16.4 | 164 | 374 | — | 219 | 0 | compact | full |

- 예전 값(탭 `clamp(fs×1.75, 40, 44)`, 목록 `sy + m ~ hy − 4`)과 비교한다.
  - 탭이 40px이던 가로 화면(1024×768·휴대폰 가로)은 탭이 4px 커진 만큼을 목록 위아래 간격에서 돌려받아 선택지 영역이 같다(844×390 224 → 224).
  - 세로(390×844)는 선택지 영역이 무대 높이 − 간격이라 4px 늘었다(215 → 219).
  - 1280×720·1920×1080은 2~3px 늘었다(1280×720 482 → 485).
  - dense 단계는 단위 테스트의 기대값(844×390 노치 0, 667×375 0, 740×320 1, 740×280 2, 740×232 3)과 모두 같다.
- 탭은 휴대폰 가로(844×390 노치·667×375·740×280)에서 44px, 1920×1080에서 45.5px이다.
- 1280×720 탭 띠 위끝 69.5%는 단위 테스트가 `toBeCloseTo(0.695, 2)`로 지킨다. 글자 크기 '더 크게'(1.25)면 대사창이 커져 63.5%가 되어 1280×720도 `cgfit=low`다('크게' 1.12는 66.4%로 full).

### 9.2 넘침 안전장치 (`textbox.ts`)
- `--tb-grow`를 **`#vn` 루트에** 설정한다. 그러면 `.textbox`와 `.qbar`가 같이 위로 올라간다.
- 늘릴 수 있는 한도: `maxGrow = hy − (sy + m)`. 빠른 메뉴 탭의 위끝이 무대 위 여백보다 올라가지 않는다.
- 글자 크기를 '크게' 이상으로 하면 3줄을 넘는 문장이 생길 수 있다(예: 740×320에서 '더 크게'는 한 줄 약 25자). 이때는 이 안전장치가 처리한다. 대본 검증(`LINE_MAX_CHARS`)은 '보통' 기준을 유지한다.

- **대비**:
  - 본문 14.2:1, 보조 8.2:1, 안내 5.3:1. 이름표 흰 글자 4.7~6.2:1.

  - 밤 유리 글자는 13.9:1이다.

- **포커스**: 6.16의 이중 링. 버튼·탭·슬롯·슬라이더·스위치 모두에 적용한다. 목업의 메뉴 화면 '저장하기' 타일이 그 예다.

- **글자**:
  - 휴대폰 가로에서 16px 미만 글자는 없다(목업 자동 점검 0건).
  - 글자 크기 3단계, 글자 속도 미리보기를 제공한다.
  - 기록에서는 독백·선택·날짜를 색과 모양 두 가지로 구분한다(색만으로 구분하지 않는다).
- **스크린리더**:
  - 대사 live 영역, `.text`·`.name`의 aria-hidden은 지금과 같다.
  - 시트는 `role=dialog`에 sr-only h2로 이름을 붙인다. 탭은 `tablist/tab/tabpanel`과 `aria-selected`를 쓴다.
  - 쪽 레일은 `nav[aria-label=쪽]`과 `aria-current=page`, 글자 크기는 `radiogroup`을 쓴다.
  - 빠른 메뉴는 `role=toolbar`다. 아이콘만 보이는 단계에서도 글자는 textContent에 남겨 둔다(compact는 숨긴 버튼 자체를 빼는 방식).
  - 미리보기는 `aria-hidden`이다.
- **움직임**: `prefers-reduced-motion`과 빛망울 끄기 설정(8장).
- **입력 누수 방지**: `.qbar`, `.choices`, `.autosave-chip`, 오버레이, 타이틀, 엔딩, `.rotate`는 `[data-noadvance]`를 유지한다. 숨기기 복귀 입력은 대사를 넘기지 않는다.
- **저장 경고**: 자동 저장을 브라우저에 쓰지 못한 순간의 경고 토스트는 `role=alert`(바로 읽음), 회복·일반 토스트는 `role=status`. 상태 표시의 접근 이름은 "이 탭에만 저장됨 (자동 저장 안내)"·"공간 부족 · 저장됨 (자동 저장 안내)"처럼 보이는 글자로 시작하고 좁은 화면에서도 같다.

## 부록 A. 현재 코드 결함 (재디자인과 함께 고칠 것)

대화 기록 항목의 클래스가 `log-item ${kind}`라서 `card`와 `choice`가 그대로 클래스 이름이 된다.
- **날짜 카드 항목**: 무대 카드용 `.card { position: absolute; inset: 0; opacity: 0 }`을 물려받아 **기록에서 보이지 않는다**(개발 서버에서 확인).
- **선택 항목**: 선택지 버튼 `.choice`의 스타일(배경, 최소 높이, 등장 애니메이션)을 받는다. 그래서 흰 선택지 버튼 모양에 연한 글자로 그려져 거의 읽히지 않는다.
- **테스트 영향**: 기록이 열려 있으면 `page.locator('.choice')` 개수에도 섞인다.

고치는 법: 기록 항목은 `log-item is-${kind}`로 쓰고, 무대 카드는 `.stage > .card`로 범위를 좁힌다.
