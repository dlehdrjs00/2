# 내일도 같이 갈래? (가제)

일본 학원물 애니메이션 분위기의 짧은 **학원 일상 러브코미디 비주얼노벨** 웹게임 — 첫 플레이 버전(v0.1).
설치 없이 브라우저에서 실행되며 PC와 휴대폰 가로 화면에 맞춰 만들었습니다.

- 주인공 아오야마 소우타(1인칭, 그림 없음)와 두 히로인: 소꿉친구 **미즈하라 아카네**(츤데레) · 전학생 **사쿠라이 히나**
- 공통 이야기(선택지 4번: `c3.ch` `c4.ch` `c6.ch` `c7.ch`) → 누적 점수로 루트 결정(동점이면 마지막에 고른 히로인) → 히로인 본편 → 여름 축제 후일담(고백) → 엔딩 2개
- 이름·학교·날짜는 임시값이며 `src/story/config.ts` 한 곳에서 바꿉니다.
- 그림: 캐릭터 스프라이트 30장·이벤트 CG 11장·타이틀 키 비주얼은 **최종 일러스트**, 배경·음악·효과음은 아직 **임시**입니다. → [에셋 상태와 교체 방법](#에셋-상태와-교체-방법)
- 분량·추정 플레이 시간(`npm run validate` 출력 그대로. '본편'은 공통 + 루트 본편이고, 조합 평균 글자 수를 1분에 380~550자로 나눈 값입니다):

  ```
  장면 21개 · 대사 383줄 · 선택지 4개 · 선택 조합 16개
    · 아카네 루트 (8개 조합): 본편 175줄/5709자 ≈ 10.4~15.0분 · 후일담 55줄/1711자 ≈ 3.1~4.5분
    · 히나 루트 (8개 조합): 본편 174줄/5718자 ≈ 10.4~15.0분 · 후일담 54줄/1908자 ≈ 3.5~5.0분
  ```

## 실행

Node.js 22 를 권장합니다(배포 워크플로가 22 를 씁니다).

```bash
npm ci             # package-lock.json 그대로 설치
npm run dev        # 개발 서버 http://localhost:5173  (0.0.0.0 으로 열려 같은 네트워크의 휴대폰에서 http://<PC의 IP>:5173)
npm run build      # 타입 검사 후 dist/ 에 정적 파일 생성
npm run preview    # 빌드 결과 미리보기 http://localhost:4173  (0.0.0.0 으로 열림)
```

- 주소 끝에 `?debug` 를 붙이면 브라우저 콘솔에서 `window.__vn.info()` 로 현재 상태(장면·문장 id·루트·점수 등)를 볼 수 있습니다.
- 저장·설정·읽은 대사·본 엔딩·본 CG 기록은 브라우저 로컬 저장소(`ashita.*` 키)에만 남습니다(기기 간 동기화 없음).

## 검사

```bash
npm run check                  # 타입 검사 + 스토리 검증 + 단위 테스트 + 빌드를 한 번에
npm run typecheck              # tsc --noEmit
npm run validate               # 스토리 연결·id·에셋 파일·전 분기 시뮬레이션·루트 규칙·추정 플레이 시간
npm run validate -- --paths    # 모든 선택 조합과 도달 루트 출력
npm test                       # 단위 테스트(Vitest, tests/unit): 엔진·루트 규칙·저장/복구·저장소·화면 배치·CG
npm run test:e2e               # 브라우저 테스트(Playwright, tests/e2e) — 먼저 npm run build
npm run docs                   # docs/SCRIPT.md(검토용 대본)·docs/ASSETS.md(에셋 목록) 다시 생성
```

- `npm run test:e2e` 는 `vite preview` 로 `dist/` 를 `127.0.0.1:4173` 에 띄워 돌립니다(이미 떠 있으면 그 서버를 씀). 그래서 **빌드를 먼저** 해 두어야 최신 코드가 검사됩니다.
- E2E 프로젝트: `desktop`(1280×720), `phone-landscape`(844×390), `phone-se-landscape`(667×375, 둘 다 터치·고해상도 에뮬레이션). 두 엔딩 끝까지 플레이, 선택 조합별 루트, 저장·불러오기·손상 데이터 복구, 자동/건너뛰기, 입력 중복 방지, 화면 배치, 세로 화면 안내, 오디오 실패 시 진행, 새 화면(숨기기·퀵저장·탭 시트·설정) 등을 확인합니다.

## 기능

- **무대와 대사창**: 16:9 무대를 화면에 최대한 크게 놓고, 남는 여백은 배경을 흐려 채웁니다. 노치(안전 영역)를 피하고, 휴대폰을 세로로 들면 가로로 돌리라는 안내가 뜹니다(세로로 계속하기도 가능). 밤 장면은 대사창이 남색 유리로 바뀝니다.
- **빠른 메뉴**: 대사창 위 테두리에 붙은 탭 — 기록·자동·스킵·퀵저장·퀵로드·숨기기·설정·메뉴.
- **탭 시트**: 저장하기·불러오기·설정·대화 기록을 한 창 안에서 탭으로 오갑니다(←/→ 키로도 이동).
- **저장**: 수동 30칸(5쪽 × 6칸) + 자동 저장(대사·선택지가 바뀔 때마다, 엔딩에 닿으면 지움) + 퀵저장 1칸. 칸마다 저장 당시 무대 썸네일·장면 제목·대사·루트 배지가 보입니다. 타이틀의 [이어하기]는 자동 저장에서 다시 시작합니다. 대사를 고쳐 저장 위치를 찾지 못하면 "그 장면 처음부터" 복구를 제안합니다.
- **대사창 숨기기(H)** · **퀵저장 F5 / 퀵로드 F9**
- **설정**: 글자 속도 · 자동 진행 속도 · 대사창 불투명도 · **글자 크기**(보통/크게/더 크게 = ×1/1.12/1.25) · 배경음/효과음 음량 · 전체화면 · **빛망울 효과**(무대 위 빛망울·햇살 켜고 끄기). 미리보기 무대에서 바로 확인할 수 있고 바꾸면 바로 저장됩니다.
- **대화 기록**: 화자 색 이름표, 독백·날짜 카드·고른 선택지를 모양으로 구분합니다.
- **이벤트 CG 11장**: 주요 장면에서 무대 가득 표시되고, 배경이 바뀌면 자동으로 걷힙니다. 저장·불러오기 때도 복원됩니다.
- **추억 앨범**: 타이틀의 추억 앨범에서 본 이벤트 CG 다시 보기(본 CG 는 전역 기록에 남음).
- **엔딩 폴라로이드**: 엔딩 화면에 루트 대표 CG(아카네 「처음 바래다주는 길」, 히나 「첫 장에 넣을 사진」)를 폴라로이드로 보여 주고, 본 엔딩 메달과 타이틀의 엔딩 배지가 남습니다.
- **느린 망**: 그림을 다 받아 해독한 뒤에 무대를 바꾸고 대사를 보여 줍니다(최대 8초. 1.2초 넘게 걸리면 '그림을 불러오는 중…', 기다리는 동안 누르면 기다림만 끝나고 줄은 넘어가지 않음). 이미 보이는 인물의 표정·옷만 바뀐 줄은 1초까지만 기다리고, 그동안은 이전 그림이 그대로 보입니다. 곧 볼 그림은 지금 무대 그림을 받은 뒤 미리 받아 둡니다. 데이터 절약 모드에서는 타이틀 키 비주얼을 작은 그림으로 쓰고 게임 전체 그림을 미리 받지 않습니다. → [UI_DESIGN 6.20](docs/UI_DESIGN.md)
- **웹 앱 매니페스트**: 홈 화면에 추가하면 가로 전체화면으로 열립니다(서비스 워커는 없어 오프라인 실행은 되지 않습니다).

### 대본 작성 규칙 요약

- 대사·카드·선택지·엔딩·라벨에는 고유 id(`c1.010` 형식)를 직접 붙입니다. 저장 위치와 읽음 기록이 이 id 를 가리키므로
  대사를 추가·삭제해 배열 순서가 바뀌어도 저장이 깨지지 않습니다. 이미 공개한 id 는 바꾸지 마세요.
- 이름은 `{osana}`, `{tenko:는}`, `{me:를}` 처럼 치환 키로 씁니다(조사 자동).
- 이벤트 CG 는 `cg('rain_osana')` 로 띄우고 `cg(null)` 이나 `bg(...)` 로 걷힙니다.
- 수정 후 `npm run validate` 로 연결 오류와 분기를 확인하고 `npm run docs` 로 문서를 갱신하세요.

## 에셋 상태와 교체 방법

| 분류 | 수량 | 상태 |
|---|---|---|
| 캐릭터 스프라이트 | 30장(아카네 12 · 히나 18) | 최종 — 사용자가 준 일러스트(원본 1600×2400), 게임 파일 WebP 1200×1800 |
| 이벤트 CG · 타이틀 키 비주얼 | 11장 + 1장 | 최종 — 사용자가 준 일러스트, WebP 1920×1080(+썸네일 480×270) |
| 배경 | 19종(대본 18 + 타이틀 대체 1) | **임시** — 코드로 그린 SVG |
| 음악 · 효과음 | 6곡 · 10종 | **임시** — 코드로 합성한 MP3 |

- 글꼴: Pretendard·고운돋움·고운바탕·주아(npm 패키지, 외부 CDN 없음)와 타이틀 로고·부제 글자만 남긴 부분 글꼴 2개(`src/ui/styles/fonts/`)는 모두 SIL Open Font License 1.1 입니다. 저작권 표기와 라이선스 전문은 `public/licenses/fonts-OFL.txt` 에 있고, 빌드하면 `dist/licenses/fonts-OFL.txt` 로 함께 배포됩니다.
- 타이틀 화면 버전 표시 뒤의 「임시 배경·음악」 안내는 모든 항목이 최종으로 바뀌면 자동으로 사라집니다.
- **배경·음악·효과음 교체**: 파일을 `public/assets/` 아래 새 폴더(예: `public/assets/bg/`, `public/assets/audio/`)에 넣고, `src/story/assets.ts` 의 해당 항목 `src` 를 바꾸고 `placeholder: false` 로 바꾼 뒤 `npm run validate` → `npm run docs`.
  - 배경: WebP(또는 JPEG) 1920×1080(16:9), 시간대(낮·노을·밤)를 `tone` 과 맞춤.
  - 음악: MP3/M4A, 끝과 처음이 이어지는 루프(파일 전체가 반복됨), 곡끼리 음량 맞춤.
  - 효과음: 앞 무음 없이 바로 시작하는 짧은 MP3/M4A.
  - 직접 만들었거나 상업 이용 가능한 라이선스의 소재만 쓰고 출처를 기록합니다.
- **캐릭터·CG 그림을 다시 바꿀 때**: `art-inbox/char/{osana,tenko}/{outfit}_{hair}_{expr}.png`, `art-inbox/cg/{id}.png` 에 넣고
  `python3 scripts/import-art.py --dry-run --strict`(검사) → `python3 scripts/import-art.py`(변환). Python 3 + Pillow + numpy 필요. `art-inbox/` 는 저장소에 넣지 않습니다.
- 자세한 사양(권장 해상도·용량·음량·라이선스 조건), 인물 배치 수치, 대사창이 덮는 범위, CG 별 대본 위치, `import-art.py` 옵션은 → **[docs/ASSETS.md](docs/ASSETS.md)**

## 배포 준비

- `vite.config.ts` 의 `base: './'` 로 **상대 경로 빌드**를 합니다. `dist/` 를 어느 하위 경로(예: `https://<사용자>.github.io/<저장소>/`)에 올려도 동작합니다.
  JS/CSS 는 `assets/[name]-[hash].*` 로 나와 배포마다 캐시가 갈리고, `public/` 아래 파일은 이름 그대로 복사됩니다.
- `dist/` 폴더를 정적 호스팅(GitHub Pages, Netlify, 사내 웹서버 등)에 그대로 올리면 링크로 플레이할 수 있습니다.
- GitHub Pages 워크플로 `.github/workflows/deploy-pages.yml` 는 **수동 실행 전용**(`workflow_dispatch`)이라 push 로는 배포되지 않습니다.
  1. 저장소 Settings → Pages → Source 를 **GitHub Actions** 로 바꿉니다.
  2. Actions 탭에서 "Deploy to GitHub Pages" 를 골라 **Run workflow** 를 누릅니다.
  3. 워크플로는 Node 22 에서 `npm ci` → `npm run typecheck` → `npm run validate` → `npm test` → `npx vite build` 후 `dist/` 를 Pages 에 올립니다(E2E 는 브라우저가 필요해 돌리지 않음).
